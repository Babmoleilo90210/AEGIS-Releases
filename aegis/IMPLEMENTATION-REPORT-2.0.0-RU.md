## Реализованная компоновка и исправления

Пять категорий настроек имеют одинаковые размеры, общую тематическую скруглённую подложку и содержимое **ниже** категорий. Единая прокрутка сохраняет доступ при200% и800×600. Возвращены прежние notification preferences, доступ к сессиям и управлению архивом. Русские названия переносятся.

Архив сохраняет все операции и три представления, основные действия отделены от меню дополнительных. Поиск содержит одну строку и шесть скрытых фильтров; фильтр «Отправитель» исходящего письма теперь использует собственное имя, не получателя. Защищённое содержимое letter-password/FF1 поиском не раскрывается; plaintext-индекс на диске не создаётся.

Профиль ограничен по ширине, аватар можно увеличить/изменить/удалить. Исправлены устаревшее изображение контакта после синхронизации, обработка удаления/скрытия и гонка, при которой старый ответ публикации сбрасывал более новое pending-изменение. EXIF/ненужные метаданные удаляются при сохранении и перед публикацией старых изображений. Подписанный удалённый payload не переписывается. Новые публичные профили доступны по умолчанию; сохранённый выбор приватности не сбрасывается.

Общая система кнопок использует токены Appearance Engine, сохраняет16 пресетов, пользовательские темы/макеты/шрифты и плотность. Safe Web добавляется в пользовательский порядок навигации идемпотентно; предыдущий порядок сохраняется.

## Safe Web

Панель позволяет установить официальный пакет с .asc, выбрать обычную/временную сессию, открыть явный HTTPS/onionURL, явно перезапустить сессию, закрыть браузер, просмотреть загрузки и импортировать выбранное в архив. Неподдерживаемых remote-команд, WebView и своего движка нет. Уровень безопасности и «Новая личность» остаются штатными функциями Tor Browser.

До распаковки/исполнения Java/Bouncy Castle проверяет OpenPGP с pinned Tor primary fingerprint `EF6E286DDA85EA2A4BA7DE684E2C6E8793298290`, binding/back signature, отзывы/сроки/алгоритмы и точные байты. TAR/XZ распаковывается ограниченно и безопасно; Windows portable EXE исполняется только после проверки. Полный официальный Tor Browser не включён: в доступной среде загрузка актуального пакета/подписи вместо бинарных данных возвращает блокирующий HTML. Ни фактическая установка, ни actualversion не выданы за PASS.

Шаблоны и trusted receipts не монтируются в браузер. Постоянные и временные сессии раздельны; копирование атомарно, повреждённые binaries отвергаются, silent rehash запрещён. Постоянные Data/закладки переносятся только в новый проверенный пакет. Временные данные удаляются после подтверждённого завершения; физическое secure erase не обещается.

Linux backend — bubblewrap namespaces, private slirp network и вложенный Xephyr с отдельным cookie. Host home, АЕГИС, D-Bus и host clipboard/display socket не передаются. Windows backend — Microsoft WSB CLI, собственный VM ID и host-проверка остановки; отображается только отдельный browser bundle, отключены clipboard/записывающие устройства. Требуются Windows11 **24H2+ Pro/Enterprise/Education** с актуальным Windows Sandbox. Поддержка других редакций/builds не заявлена. Экспериментальный AppContainer helper не является штатным маршрутом.

Исправлены потеря ownership при неудачном запуске/закрытии, повторный запуск до завершения, удаление mapped временного профиля до остановки VM и блокировка FX во время проверки пакета. Медленные операции выполняются отдельным worker, UI читает cached snapshot. Ошибка остановки сохраняет ресурсы/блокировку для повторного закрытия. На Windows приватная host-запись VM ID позволяет сверить/остановить только прежнюю собственную среду до очистки остатков после аварии.

Загрузка не исполняется автоматически. Перед импортом создаётся ограниченный snapshot через защищённые каталоговые/файловые handles вне mounts браузера; только он передаётся существующему EncryptedArchive. Ключ архива браузеру не передаётся. Это исправляет гонку проверки пути с последующим чтением ссылки.

Штатный updater Tor Browser не заменён. Изменившиеся binaries требуют повторной аттестации свежим подписанным пакетом. Полная совместимость MAR update пока NOT_RUN. Подробности и модель угроз — SAFE-WEB-2.0.0.md и SAFE-WEB-THREAT-MODEL-2.0.0.md.

## Реальная сеть, профили и нативная приёмка

Дважды запускался настоящий bundled Tor с новым staging-профилем. Direct остался0%; Snowflake дошёл до10%, фиксировался `SNOWFLAKE_BROKER_ERROR`, готовность не наступила. Поэтому все семь сквозных A/B avatar/profile операций через настоящий onion остались **NOT_RUN**. Процессы/временные данные этих probes закрыты. RESULTS.json и очищенные technical logs находятся в `docs/test-results/2.0.0-followup/tor-profiles/`.

Локальная интеграция действительно использует два аккаунта, SQLite, подписи и wire protocol через контролируемый SOCKS harness; она подтверждает обновление/скрытие/удаление/offline reopen в этом окружении, но не подменяет Tor или production Relay. Production capability не проверена и сервер не менялся. Nickname является регистрационным индексом; корректное переименование требует новой согласованной серверной операции. Конкретное ТЗ: RELAY-PROFILE-NICKNAME-PROPOSAL-2.0.0.md. Поле пока явно read-only; этот пункт не выполнен.

Windows11 x64, CachyOS KDE Wayland и X11 — **NOT_RUN**. Нужные desktop-системы отсутствуют; контейнер также запрещает NETLINK_ROUTE для полного Linux sandbox. Cross-compiled PE, headless сцена, конфигурация VM и unit tests не заменяют эти проверки. HTTPS/onion, DNS/WebRTC/capture, actual isolation/clipboard/browser lifecycle и MAR update пока не подтверждены. Kernel Tor-only firewall против полного browser-broker compromise не заявляется; штатная модель Tor Browser сохранена, пределы описаны в threat model.

## Миграция, updater и подготовка

До открытия новых sidecars ClientUpgrade.beforeVersionOpen создаёт/проверяет полный ciphertext/settings snapshot; повторное открытие идемпотентно. Тесты сохраняют реальные fixture identity keys, письма, архив, темы и пользовательский порядок. Данные АЕГИС в браузер не копируются. Нативная установка поверх1.5 и полный owner-signed updater download/install/restart/rollback — **NOT_RUN**. Manifest-only успех за E2E не считается.

Windows Setup/portable, CachyOS AppImage, source/client-source и native kit готовятся из одного фиксированного runtime tree; SHA-256 и структурные результаты записываются после упаковки. Все величины артефактов — в SHA256SUMS/ARTIFACT-VERIFICATION.json, provenance — SOURCE-PROVENANCE-2.0.0.json. Native kit содержит отдельные test JAR, не меняет production classpath и не помечает автоматом native PASS.

Инструкции: README-WINDOWS.md, README-CACHYOS.md, MIGRATION-1.5.0-TO-2.0.0.md, NATIVE-ACCEPTANCE-2.0.0.md. Для оставшегося updater E2E нужен окончательный тестовый manifest, подписанный владельцем **офлайн**; приватный ключ в Work/CI/VPS не передаётся. Stable feed/подпись/публичный релиз не меняются. OWNER-OFFLINE-SIGNING-2.0.0.md описывает точные байты/проверку, без самостоятельной production подписи.

Оставшиеся обязательные действия перечислены в RELEASE-GATES-2.0.0.json и SW/UI матрице FINAL-VERIFICATION-2.0.0.json. Автоматический успех не переводит productionReady в true. Законченная версия по полному ТЗ пока не объявляется готовой.
