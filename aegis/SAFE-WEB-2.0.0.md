# Safe Web 2.0.0

Статус: реализация для испытаний. `productionReady=false`. Работоспособность официального Tor Browser и сетевые свойства на целевых платформах ещё не подтверждены нативной приёмкой.

## Установка и доверие

Safe Web использует официальный Tor Browser отдельным процессом, со штатным Tor и штатным браузерным профилем внутри отдельного пакета. WebView, собственный движок, почтовый SOCKS и пользовательский Firefox не используются. АЕГИС не передаёт браузеру объекты identity, пароли, письма, ключи архива или cookie Tor мессенджера.

В разделе Safe Web выберите «Установить / обновить Tor Browser…», официальный стабильный Linux x86_64 `.tar.xz` либо Windows x86_64 portable `.exe`, затем соответствующую `.asc`. Получайте оба файла с <https://www.torproject.org/download/>. До распаковки/исполнения проверяются точные байты пакета, OpenPGP-подпись и закреплённый первичный fingerprint Tor Browser Developers `EF6E286DDA85EA2A4BA7DE684E2C6E8793298290`. Проверка выполняется Java/Bouncy Castle; отдельные Python/GnuPG пользователю не нужны. Изменённый пакет не запускается. Неофициальные ключи и локальный список SHA-256 не заменяют подпись. Подробности — `SAFE-WEB-DISTRIBUTION-AUTH-2.0.0.md`.

Установщик копирует входные файлы в закрытый staging, проверяет подпись, ограничивает размер/число записей и безопасно обрабатывает внутренние ссылки. Внешние ссылки, особые файлы и выход за каталог отвергаются. На Windows только после проверки запускается штатный portable-установщик в новый отдельный каталог. Прежний пакет не перезаписывается. Имя пакета не является криптографическим доказательством номера версии; фактическая версия проверяется дополнительно в нативной приёмке.

Tor Browser в дистрибутив АЕГИС сейчас не включён: официальный актуальный бинарный пакет не удалось получить в этой среде. Ответ HTML «Site Unavailable» не считается загруженным браузером. Не заменять его устаревшим или сторонним браузером.

## Сессии и данные

Linux: отдельный соседний с профилем приложения каталог `aegis-safeweb`. Windows: `%LOCALAPPDATA%\AEGIS-SafeWeb`. Внутри раздельны `templates`, `bundles` и `control`. Подлинный шаблон и проверочная запись находятся вне файловой системы браузерного процесса. Копирование/публикация сессий атомарны; частичная копия не становится рабочим профилем. Межпроцессная блокировка предотвращает одновременное управление одним хранилищем.

- Обычная сессия сохраняет настройки, закладки и загрузки в собственном пакете. Установка нового проверенного пакета переносит только браузерные Data и загрузки, не файлы АЕГИС.
- Временная сессия получает отдельную копию штатного пакета. После подтверждённого завершения удаляются её профиль, загрузки и управляющие временные файлы. После аварии остатки очищаются при следующем захвате исключительной блокировки. Это удаление файлов, не гарантированное физическое стирание на SSD/журналируемой ФС.

«Новая сессия» явно закрывает вкладки и перезапускает выбранный режим. Для штатной функции «Новая личность» используйте меню Tor Browser. Открытие ссылки при работающем браузере требует подтверждения перезапуска либо использования его адресной строки: неподдерживаемые remote-команды и автоматизация привилегированного browser chrome не применяются.

## Linux: KDE Wayland и X11

Нужны установленные системные `bubblewrap`, `slirp4netns`, `Xephyr`, локальный X11/Xwayland и разрешённые непривилегированные user namespaces. Отсутствие любого компонента прекращает запуск; обычный неограниченный процесс не подставляется.

Bubblewrap создаёт отдельные mount, PID, IPC, user и network namespaces, сбрасывает capabilities и окружение. Внутри доступны только системные библиотеки/шрифты/сертификаты для выполнения, собственный пакет, собственные загрузки и один вложенный X-дисплей с отдельным cookie. Host home, каталог АЕГИС, D-Bus, host Wayland и host X socket, аудио и системный буфер обмена не передаются. Xephyr показывает отдельное окно на локальном X11/Xwayland; это доверенный компонент границы.

Slirp обслуживает только этот network namespace, с отключённым host loopback. Штатный браузер использует собственный Tor. Запуск отклоняется, если приватные пути АЕГИС/выбранного архива попадают в доступные системные mounts. Вложенный дисплей и сетевой помощник имеют собственные каналы владения: закрытие/EOF и завершение компонента останавливают принадлежащие сессии процессы.

## Windows

Backend использует официальный Windows Sandbox CLI с собственным случайным ID и штатный Tor Browser внутри гостевой Windows. Требуются Windows 11 24H2 или новее, поддерживаемая редакция Pro/Enterprise/Education, установленный Windows Sandbox/CLI и виртуализация. Home и старый механизм запуска без управляемого ID не поддерживаются; АЕГИС не включает компоненты ОС и не запускает браузер без изоляции.

В гостя отображается только собственный пакет, не профиль АЕГИС или домашний каталог. Отключены clipboard, принтеры, camera/audio input и vGPU; включён Protected Client. URL передаётся как ограниченные Base64-данные, не вставляется в PowerShell-код. Фиксированный скрипт запускает браузер в собственном guest Job Object. Host CLI завершает только среду с принадлежащим АЕГИС ID; сообщения гостя сами по себе не доказывают остановку VM. Подробнее и ограничения — `packaging/windows/SAFEWEB-NATIVE-NOTES.md`.

Экспериментальный AppContainer helper не используется как штатный backend: совместимость официального многопроцессного Firefox с внешним AppContainer не доказана. Защитные функции Firefox ради такого запуска не отключаются.

## Сеть, безопасность и статус

Tor Browser сохраняет штатные proxy, DNS, WebRTC и fingerprinting-настройки. Расширения не устанавливаются; clearnet fallback для web-адресов не добавляется. Браузерный Tor не связан с Tor почты. АЕГИС показывает состояние собственных процессов и требует проверять подключение в самом Tor Browser; почтовые 100% Tor не отображаются как статус браузера.

Отдельный namespace/VM не является kernel Tor-only firewall против полного захвата привилегированного browser broker. Tor и его bridges должны иметь внешнее соединение; на Windows гостевая ОС также имеет собственные сетевые службы. Абсолютная изоляция и защита от глобальной корреляции трафика не заявляются. HTTPS/onion, DNS/WebRTC и отсутствие прямых browser-соединений проверяются на целевой платформе с привязкой наблюдений к процессам, а не по одному факту использования Tor.

## Ссылки и загрузки

В письме пользователь явно выбирает URL и Safe Web. Передаётся только этот адрес; автоматического открытия нет. Разрешены HTTPS и HTTP onion v3. Отклоняются file/javascript/data, credentials в URL, локальные адреса, управляющие символы и аргументы команд. DNS-поиск в валидаторе не выполняется.

Загрузки остаются в `aegis-downloads` отдельной сессии. Ничего не запускается автоматически и не попадает в архив автоматически. Список исключает ссылки, вложенные каталоги и незавершённые `.part`. Явный импорт сначала делает ограниченный неизменяемый snapshot через защищённые файловые/каталожные handles в недоступном браузеру staging, затем существующий EncryptedArchive шифрует его. Snapshot удаляется после фоновой операции. Браузер не получает ключ архива. Во временном режиме импортируйте нужное до закрытия.

## Официальные обновления

Штатный updater Tor Browser не заменён. Если обновление меняет проверяемые файлы, следующий запуск потребует свежий официальный подписанный пакет: тихое повторное хэширование изменившегося браузера запрещено. Постоянные Data/закладки сохраняются при установке новой версии. Полный цикл официального MAR-обновления с этим порядком ещё NOT_RUN и является release gate.

## Фактические проверки

Реальные криптографические unit-тесты, TAR/XZ boundary-тесты, файловые/сессионные проверки и headless JavaFX проверяют отдельные свойства реализации. Они не заменяют запуск официального Tor Browser, network capture и нативную приёмку Windows 11/CachyOS. Для этих действий, недоступных здесь, в итоговой матрице сохраняется NOT_RUN. Не публиковать Stable до закрытия обязательных gates.
