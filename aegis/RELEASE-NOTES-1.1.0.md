# АЕГИС 1.1.0 — кандидат

Дата подготовки: 9 октября 2026. Production Ready: **false** до обязательной нативной приёмки. Опубликованная версия 1.0.0 и production Relay 0.2.0 не меняются.

## Исправления

- BUG-01: профиль открывается в центральной части окна; убрана зависимость этой страницы от оформления отдельного Dialog.
- BUG-02: изменить можно только собственный аватар. Чужие аватары принимаются только в подписанном профиле с проверкой закреплённой идентичности. Старые локальные подстановки не отображаются. Входящие изображения ограничиваются по формату/размерам даже при корректной подписи владельца.
- BUG-03: в основном окне и просмотре письма одна собственная панель управления; дополнительная кнопка Close скрыта в диалогах.
- BUG-04: масштаб 80–200% меняет геометрию всей Scene, шрифты, значки и диалоги; системный DPI JavaFX не переопределяется. Настройка сохраняется.
- BUG-05: переписка использует onion-only SOCKS; HTTPS updater — второй SOCKS-порт того же встроенного Tor. Прямого подключения нет.
- BUG-06: подписанные неизвестные отправители сохраняются без автоматического доверия, получают ACK и не задерживают следующие письма. Блокировки локальные; повреждённое содержимое одного письма не прерывает поиск остальных.
- BUG-07: оформление не пересоздаёт активный редактор. Черновик, выбранные файлы, TTL и вручную введённые секреты остаются в памяти; выход очищает их.
- BUG-08: update startup ACK перенесён после открытия хранилища, построения основного окна и локальной self-test E2EE. До подтверждения доставка нового клиента приостановлена.
- BUG-09: резервная копия перед установкой включает весь зашифрованный vault, настройки, аватары, публичный cache, receipts, локальную сессию и собственный Tor state, signed updater history/floors. Полный первый backup создаётся и для уже modern vault 1.0. Identity backup не выдаётся за полный backup.
- BUG-10: перезапуск Tor закрывает старые Control/P2P, повторно выполняет SAFECOOKIE и публикует новый временный onion; постоянные identity keys не меняются.

## Новые возможности

Центральный профиль с неизменяемым ником, публичным «О себе», собственным JPG/PNG/WebP до 2 МБ и обрезкой в памяти. Публичные данные по умолчанию скрыты. Профили и согласия дружбы подписываются локальной Ed25519 identity.

Список друзей определяется по двум подтверждённым согласиям. Удаление дружбы сохраняет контакт и письма. Offline отзыв согласия сохраняется зашифрованно и публикуется после повторного входа в сеть, даже если контакт был удалён. Добавлены локальные закрепления, папка заблокированных писем, отметка «Неизвестный», отдельные признаки подписи и доверенного контакта, локальный поиск по нику, теме, дате и папкам.

Добавлены карточки ответов, цепочки и пересылка с подтверждением. Ответ на защищённое письмо требует нового вручную введённого пароля и FF1 code. Обычная E2EE-переписка открывается автоматически. Новые структурированные ссылки используются для совместимых получателей; обычные одиночные письма сохраняют читаемый для 1.0.0 формат.

Сворачиваемая навигация, собственные window controls, темы по системной настройке с ручным выбором, пресеты и переходы 150 мс. Нейтральные уведомления без текста письма/имени отправителя. На рабочих столах без SystemTray доступно уведомление внутри АЕГИС.

Локальное хранилище можно открыть без Relay. Отправка и сетевое добавление контакта требуют соединения и авторизации.

## Обновления и совместимость

Проверка при запуске и через 24 часа, проверка Ed25519 до JSON, дедупликация системных писем, загрузка с реальными байтами и продолжением через HTTP Range. Ошибки SHA-256, размера, подписи и структуры пакета запрещают установку. Установка требует подтверждения; откат сохраняет прежнее состояние.

Protocol 1 и opcodes 1–10 сохранены. Подготовлен optional staging Relay 0.3.0 с аддитивными таблицами профилей и согласий. Production Relay 0.2.0 сохраняет базовую почту; новые серверные функции на нём недоступны.

## Пока не подтверждено

Windows 11/DPI 100–200%, CachyOS KDE Wayland/X11, Direct Tor и Snowflake через внешнюю сеть, межплатформенный обмен через реальный staging VPS, reboot, нативная установка/restart/rollback. Успешная компиляция и автоматические тесты не заменяют эти проверки. Первый переход 1.0.0 → 1.1.0 — явная проверяемая установка; автоматический updater 1.0.0 не объявлен исправным.
