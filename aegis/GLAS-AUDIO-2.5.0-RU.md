# Глас 2.5.0: аудиодвижок, зависимости и фактические проверки

Аудиодвижок продолжает Java-архитектуру АЕГИС. Java Sound обслуживает устройства ввода и вывода; JNA вызывает комплектные официальные libopus 1.6.1 и SpeexDSP 1.2.1. Собственного аудиокодека, имитации шумоподавления, записи разговоров и временных аудиофайлов нет. Сеть, аутентификация и согласие на звонок находятся в `VoiceCallService`/TLS-транспорте; аудиодвижок не создаёт сокеты.

## Контракт согласия и управления

`GlasAudioSession.start(Config, EncodedSink, Listener)` вызывается контроллером только после принятия звонка и аутентификации собеседника. Он открывает воспроизведение, но оставляет микрофон закрытым. Только `setMicrophoneEnabled(true)` открывает выбранный `TargetDataLine`. Выключение микрофона закрывает линию, увеличивает поколение захвата и запрещает передачу кадра, полученного старым поколением. Контроллер дополнительно очищает собственную очередь отправки при выключении микрофона. При звонке, который ещё не принят, не следует создавать аудиосессию.

Доступны выбор микрофона/выхода, переключение без перезапуска звонка, усиление ввода 0–2, громкость воспроизведения 0–1, уровни RMS 0–1, настоящее эхоподавление и шумоподавление. Исчезнувший выбранный микрофон не заменяется другим автоматически. Ошибки устройства/кодека закрывают сессию и передаются контроллеру без имён устройств, аудиоданных и содержимого разговора.

`inputDevices()` и `outputDevices()` перечисляют устройства, не открывая микрофон. Идентификатор основан на данных Java Sound и позиции микшера: при изменении списка устройств сохранённый идентификатор может стать недоступен; пользователь выбирает устройство повторно. `testMicrophone(id, listener)` предназначен только для явной кнопки пользователя, показывает локальный уровень, не воспроизводит и не отправляет звук, автоматически закрывает микрофон через 15 секунд. Его также нужно закрыть при уходе со страницы/запуске звонка.

## Формат и ограничение задержки

Внутри устройства используется mono PCM signed 16-bit little-endian, 48 000 Гц. Кадр — 20 мс / 960 отсчётов; сетевой payload — только Opus VOIP, не более 1275 байт. Decoder проверяет размер, один канал и длительность ровно 20 мс до декодирования. Декодирование потерь использует штатный Opus PLC, максимум три последовательных кадра, затем тишину.

Захват и воспроизведение работают на отдельных потоках. `EncodedSink.offer` обязан возвращать немедленно; сетевой контроллер владеет своей ограниченной очередью. Входящая очередь ограничена 15 кадрами, кадры старше 300 мс удаляются. Целевой буфер адаптируется к измеренным колебаниям поступления в диапазоне 40–180 мс. Энкодер использует 24 кбит/с и снижает скорость до 16/12 кбит/с при высоком jitter или отказах ограниченной очереди отправки. Это ограниченная эвристика, а не гарантия задержки Tor. TCP/Tor может задерживать всю последовательность из-за head-of-line blocking; код не накапливает бесконечный звуковой буфер в ответ на такую паузу.

При закрытии сессии сначала закрываются линии Java Sound, останавливаются рабочие потоки, очищается очередь и доступные PCM/packet-массивы; затем уничтожаются состояния Opus/Speex под их mutex. Каждый доступ к native-состоянию дополнительно проверяет закрытие внутри того же mutex. Если драйвер не разблокирует чтение после `close`, завершение зависит от драйвера; native-состояние после освобождения повторно не используется. Приложение не заявляет гарантированное физическое стирание всех копий Java heap.

## Настоящие AEC и NS

SpeexDSP обрабатывает каждый кадр. Denoiser использует штатный `speex_preprocess_run`; предел подавления стационарного шума — 20 dB. AGC и устаревший Speex VAD отключены; DTX выполняет Opus. Эхоподавление использует `speex_echo_capture`/`speex_echo_playback`, reference после регулировки громкости и хвост 200 мс. Preprocessor получает тот же echo-state для подавления остаточного эха. Флаги AEC/NS переключаются во время активного звонка под mutex; при смене устройства AEC сбрасывается.

Программный AEC требует согласованных часов capture/playback и разумной задержки драйвера. Разные звуковые карты, clipping, нелинейность колонок, аппаратные эффекты и задержка за пределами хвоста ухудшают результат. Автоматический синтетический тест подтверждает работу библиотеки на известной модели эха, но не заменяет проверку реальных динамиков/микрофонов Windows 11 или KDE.

Официальные сведения: https://opus-codec.org/downloads/ ; https://opus-codec.org/license/ ; https://speex.org/downloads/ ; https://ftp.osuosl.org/pub/xiph/releases/speex/SHA256SUMS.txt . API проверены по заголовкам соответствующих release-архивов; документация: https://opus-codec.org/docs/opus_api-1.6/ и https://www.speex.org/docs/manual/speex-manual.pdf . Точные лицензии включены в `docs/third-party` и в подготовленные native runtime-пакеты.

`packaging/build-voice-native.py` проверяет исходный архив до извлечения, удаляет прежние собственные каталоги исходников/объектов и собирает свежие библиотеки для Linux x86_64 или MinGW x64. В приложении нет скачивания аудиобиблиотек. Windows DLL импортируют только `KERNEL32.dll` и `msvcrt.dll`, без дополнительного GCC/pthread runtime. Linux библиотеки зависят от системных libc/libm.

Перед `Native.load` байты проверяются по SHA-256 из ресурса `voice-runtime.json`, находящегося внутри доверенного JAR, а не по изменяемому sidecar рядом с DLL. Версия Opus дополнительно сверяется с `libopus 1.6.1`. Изменённая библиотека, иной формат/архитектура или отсутствующий реестр блокируют аудио без fallback. При пересборке нужно собрать библиотеки из проверенных исходников, явно обновить compiled registry через `--compiled-registry`, пересобрать JAR и подписать весь релиз штатным офлайн-процессом владельца. Существующий несовпадающий DLL нельзя автоматически объявлять доверенным.

На Linux проверенные публичные байты библиотеки загружаются из запечатанного `memfd` (`F_SEAL_WRITE|GROW|SHRINK|SEAL`), поэтому замена исходного pathname между проверкой и загрузкой не подменяет исполняемый код. Это копия кода в памяти, не аудиозапись. Требуется поддержка sealed executable memfd; при отказе системы аудио блокируется. На Windows дескрипторы предков запрещают переименование, reparse points отвергаются; дескриптор библиотеки запрещает записи/замену на время загрузки и сохраняется вместе с маппингом. Для зависимостей применяется поиск только в System32. Эти Windows-вызовы скомпилированы, но не выполнялись в этом окружении.

## Фактически выполнено

`GlasAudioTest`: 11 тестов, 0 ошибок, 0 пропусков. Отчёт: `docs/test-results/2.5.0-glas`.

- Настоящий Opus encode/decode на синтетическом сигнале, длительность и предел пакетов, PLC, изменение bitrate.
- Настоящий Speex NS уменьшает энергию стационарного синтетического шума.
- Настоящий Speex AEC сходится на известном задержанном синтетическом эхе; отдельно проверены reference API, reset и live AEC/NS.
- Java Sound seam с искусственными устройствами и настоящими кодеками проверяет закрытый до явного включения capture, mute, смену устройств, закрытие линий и ошибки. Это не физический микрофон.
- Отказ очереди снижает реальный Opus bitrate; буфер ограничен, удаляет старые кадры и меняет целевую задержку по поступлению.
- Проверка compiled SHA-256 отвергает модифицированную библиотеку и symlink.

Linux ELF-библиотеки реально загружались и выполнялись; Windows PE x64 реально собраны, таблицы импортов проверены статически. `/dev/snd` отсутствует: реальная запись/воспроизведение, аппаратное отключение/горячая замена, качество AEC на устройствах и native Windows/CachyOS Wayland/X11 — **NOT_RUN**. Перечисление Java Sound выполнялось, но наличие рабочей аудиолинии этим не доказано. Двусторонняя речь через два Tor-клиента требует отдельной интеграционной и нативной приёмки контроллера/транспорта. Этот документ не объявляет весь релиз готовым к Stable.
