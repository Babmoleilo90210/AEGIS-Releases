# Нативная приёмка 2.0.0

Статус всех трёх целевых платформ в этой работе — NOT_RUN. Комплект и контрольные суммы не являются результатом запуска. Записывать реальные ОС/edition/build, KDE session, DPI, commit, SHA-256 клиента/браузера, время и путь к доказательству. Использовать синтетические аккаунты и отдельный профиль, без release private key.

## Платформы и интерфейс

Windows11 x64 (указать edition/build); CachyOS KDE Wayland; CachyOS KDE X11 — три отдельные строки. Windows Server и Ubuntu/Monocle не заменяют их. Safe Web Windows сейчас требует24H2+ Pro/Enterprise/Education+актуальный Windows Sandbox CLI; Home/другие builds остаются compatibility gap, не PASS всей Windows11.

На каждой платформе выполнить Run-Windows/Run-CachyOS и Run-Appearance из native kit. Проверить UI-01…26: обычное/минимальное/максимизированное окно, 100/125/150/200%, длинные русские подписи, светлая/тёмная тема. Пройти фактический основной интерфейс, не только искусственные GUI-сцены. Снимки synthetic Scene подписывать как synthetic; пользовательские секреты в кадр не включать.

Регрессия: регистрация, вход/remember/offline; Direct/Snowflake/Relay и поддерживаемый P2P; обычное/защищённое письмо/letter password/FF1; вложение, delivery/read receipts и исчезновение; архив add/search/lock/recovery/backup/restore; темы, макеты и история обновлений. Сохранять фактические шаги, результат и доказательства; не подставлять mock вместо внешней сети.

## Safe Web: SW-01…20

1. Получить текущий официальный Tor Browser и соответствующую .asc; проверить исходный URL, actualversion и SHA-256. Установить через панель АЕГИС. Изменённый пакет/чужая подпись должны быть отвергнуты до распаковки или запуска.
2. На Linux проверить системные зависимости, user namespaces и вложенный дисплей в обеих KDE-сессиях. На Windows проверить Microsoft package/alias, собственный VM ID, guest launch и доказанную host CLI остановку. Отсутствие зависимости должно давать понятную ошибку без обычного fallback.
3. Открыть HTTPS и onion v3. Записать реальные Tor Browser state, время и screenshot без приватных URL. «Процесс создан» не является Tor100% или успешным HTTPS.
4. С разрешённым системным capture/instrumentation сопоставить browser, Tor/PT и ОС. Проверить отсутствие прямых browser TCP/UDP/DNS, WebRTC leak и clearnet fallback при отключении Tor/сети. Обычные сетевые службы Windowsguest и bootstrap Tor/PT учитывать отдельно; общий namespace/VM не доказывает Tor-only.
5. Создать синтетические private-key/archive/plaintext sentinels вне browser mounts. Проверить недоступность браузеру, отдельный профиль и невозможность читать host home/clipboard/IPC. Не использовать настоящие ключи или архив пользователя.
6. Скачать безвредный синтетический файл, проверить каталог, отсутствие автозапуска, явный импорт через snapshot и расшифрованное совпадение в архиве. Проверить ссылки/reparsepoints/незавершённые файлы, ошибку чтения, большой файл и отсутствие передачи archive key.
7. Проверить повторный запуск, новую обычную/временную сессию, закрытие, сбой, AEGIS exit, kill управляющего процесса, восстановление, обновление приложения с браузером. Чужой Tor Browser/VM не должен закрываться. Перед удалением временного каталога собственная среда должна быть остановлена; secure erase не заявляется.
8. Выполнить официальное browser update, затем повторную аттестацию свежим подписанным пакетом; проверить сохранение закладок/настроек и refusal изменённых неподтверждённых исполняемых файлов. MAR compatibility без фактического цикла остаётся NOT_RUN.

## Публичные профили

Два отдельных тестовых аккаунта, реальный Tor и staging Relay с профилями. A публикует аватар; B получает actualsignedpayload; A меняет/удаляет/скрывает — B получает более новую revision и очищает старое изображение. Проверить restart/offlinecache, malformed/oversized/unsupported files и metadata removal. Операторский PublicProfileTorProbe проверяет один host/staging onion; это не production capability и не cross-platform приёмка. Production deployment требует отдельного согласования. Nickname rename — отдельное серверное ТЗ.

## Миграция и updater

Проверенная копия настоящего профиля1.5 с синтетическими письмами/архивом/темами/порядком. Снять хэши неизменных keys/data до и после миграции, проверить preliminary snapshot и повторное открытие. Затем отдельный тестовый feed с подписью владельца: обнаружение, Ed25519/version, загрузка через Tor/progress, SHA-256, подтверждение, завершение, установка, перезапуск и сохранность данных. Спровоцировать сбой установки и доказать rollback. Manifest-only проверка не считается E2E. Production stable feed не менять.

Для каждой строки поставить PASS/FAIL/NOT_RUN и приложить фактическое доказательство. Любой открытый обязательный пункт оставляет productionReady=false.
