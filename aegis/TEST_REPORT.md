# Проверки АЕГИС 0.1.0

Дата итоговой проверки: **29 сентября 2026**. Среда: Linux x86_64, Zulu JDK 21.0.12.1, Gradle 9.8.0. Это проверка реализации, не независимый аудит безопасности.

## Выполнено

Полная чистая сборка всех модулей, оба `installDist` и графический smoke test завершились `BUILD SUCCESSFUL`. **26 JUnit test cases: 0 failures, 0 errors, 0 skipped.** Параметризованные случаи четырёх современных алгоритмов считаются отдельно.

| Набор | Случаев | Что проверяет |
|---|---:|---|
| CryptoTest | 11 | Четыре AEAD, неверный пароль, порча ciphertext и TTL при заново подписанном пакете, соли/nonce, скрытое имя файла, Enigma vector, allowlist/path traversal, defensive copies |
| StorageTest | 4 | Durable ACK, дедупликация, TTL после рестарта, отсутствие plaintext в локальных файлах, неверный vault password, блокировка второго процесса, откат времени, очистка без пароля |
| TorControlTest | 2 | SAFECOOKIE challenge/response до ADD_ONION, bootstrap, отказ поддельному контроллеру |
| WireTest | 4 | Версия и размеры wire, некорректные данные, обязательный TTL, ограничения адресации |
| DeliveryTest | 4 | Offline queue, P2P, fallback, потеря ACK, отсутствие plaintext marker в трафике/БД relay, поддельный ACK, quota/expiry/signature, отказ без Tor, recipient-owned DELETE |
| IsolationTest | 1 | Клиентский crypto отсутствует в runtime relay |

Дополнительно прошла Gradle-задача `relay-server:verifyIsolation`, проверяющая зависимости relay. Runtime relay содержит только собственный модуль, common-protocol, Password4j, SQLite JDBC и SLF4J. Tink/BC/client-core отсутствуют.

`uiSmoke -PheadlessSmoke` действительно запускает JavaFX, открывает вход, настройки, создание письма, контакты и входящие с синтетическим шифрованным письмом. Проверены снимки этих экранов. Использован тестовый Monocle; это **не** проверка оконного менеджера/драйверов реального CachyOS. Основной клиент использует обычный desktop JavaFX, а Monocle не включён в его поставку. Скриншоты двух основных экранов находятся в `docs/screenshots/`.

Из собранного distribution отдельно запускался relay: `serve`, `version`, `health`, `stats`, `cleanup`, затем SIGTERM. Health и stats вернули корректные JSON-счётчики, shutdown удалил health-файл, stderr был пуст. Проверен синтаксис shell-скриптов deploy. Установка systemd/firewall на пользовательской машине не выполнялась.

## 13 сценариев из задания

| № | Требование | Результат и граница доказательства |
|---:|---|---|
| 1 | Plaintext не поступает relay | Пройден тест с уникальным marker в исходном письме: его нет в захваченном relay wire и SQLite. API принимает EncryptedPacket. Это не формальное доказательство всех возможных исполнений |
| 2 | Неверный ключ | Все 4 современных режима отвергают. Enigma по устройству исторического шифра не может определить правильность ключа |
| 3 | Порча ciphertext | Пройдены signature и AEAD authentication failure, в том числе после повторной подписи изменённого ciphertext |
| 4 | Nonce | Проверены длины и различие случайных nonce/salt между отправками; генератор SecureRandom/реализация Tink. Статистический тест не доказывает абсолютное отсутствие коллизий |
| 5 | Удаление после ACK | Пройдено, включая идемпотентный повтор и tombstone от replay |
| 6 | До ACK не удалять | FETCH сохраняет очередь; обрыв P2P ответа и relay retry проверены |
| 7 | TTL после доставки | Пройдены первый durable приём, повторная доставка без переноса срока и рестарт |
| 8 | Удаление expired | Локально, без разблокировки vault, после отката часов и на relay |
| 9 | Дубли | Один messageId даёт одно письмо и прежнее firstDeliveredAt |
| 10 | Нет clearnet fallback | SOCKS failure выдаёт ошибку; обычный hostname и внешний SOCKS адрес отвергаются |
| 11 | Две разные сети | **Не проверено в этом сеансе.** Нужны два настоящих компьютера/Tor и доступный onion relay |
| 12 | P2P при доступности | Пройдено на localhost SOCKS-стенде с отдельными endpoints; relay queue остаётся пустой |
| 13 | Relay при отказе P2P | Пройдено на том же стенде, включая потерянный ACK |

Стенд `SocksHarness` использует настоящие локальные сокеты и реализацию NetworkService, но заменяет сеть Tor. Он находится только в integration-tests и не является переключаемым обходом Tor в рабочем клиенте.

## Повторение

```bash
./gradlew clean build
./gradlew :client-ui:installDist :relay-server:installDist
./gradlew :client-ui:uiSmoke -PheadlessSmoke
```

Для обычного графического smoke test с DISPLAY уберите `-PheadlessSmoke`. После первой загрузки зависимостей эти команды можно выполнять с `--offline`. HTML/XML отчёты появляются в `<module>/build/reports/tests/test/` и `<module>/build/test-results/test/`; PNG — `client-ui/build/ui-smoke/`. В архиве исходников приложена копия XML итогового запуска в `docs/test-results/`.

## Ручная приёмка Tor перед реальным использованием

1. Разверните свой relay по SERVER_DEPLOYMENT.md. Проверьте loopback bind, закройте регистрацию после создания аккаунтов.
2. Запустите два клиента в разных сетях, например домашней и мобильной. Оба должны сверить fingerprints и добавить друг друга.
3. При обоих онлайн дождитесь P2P статуса и отправьте письмо: отправитель получает подтверждение P2P, `relayctl stats` не показывает прироста очереди. Расшифруйте вручную.
4. Выключите клиент B. Отправьте письмо с TTL 60 секунд, подождите более минуты, включите B: удаление должно произойти примерно через минуту **после получения**, а не до получения.
5. Закройте просмотр до TTL и откройте заново: ключ нужно вводить снова. Дождитесь TTL с открытым просмотром: окно закрывается. Повторите с закрытым GUI и включённым cleanup timer (точность около минуты).
6. Остановите Tor у A: отправка должна завершиться ошибкой. Независимо проверьте egress через инструкции FIREWALL.md; не считайте текст статуса доказательством firewall.
7. Проверьте выбранные максимальные файлы и RAM на своём VPS. Базовые проверки не являются длительным нагрузочным испытанием 512-МБ VPS или тестом 100-МиБ вложений.

Не заявляется проверка утечек через весь оконный стек ОС, forensic-стирания SSD, устойчивости к root/кейлоггерам, Tor traffic correlation или отсутствие всех ошибок сторонних библиотек. Эти границы описаны в THREAT_MODEL.md.
