# Нативная приёмка АЕГИС 2.5.0 — Взор и Глас

Этот документ — план и незаполненный протокол. Все строки ниже имеют начальный статус **NOT_RUN**. Наличие установщика, kit, сценария или SHA-256 не означает, что проверка выполнена. PASS записывают только после указанной реальной операции и сохранения доказательства; FAIL сохраняют вместе с причиной. Автоматические и loopback-испытания имеют собственные отчёты и не подставляются в эти строки.

`productionReady=false`, пока остаётся хотя бы один обязательный незакрытый пункт. Публикация Stable и изменение `updates/stable.json` / `.sig` данным планом не разрешаются.

## 1. Условия и регистрация стенда

Нужны два **физических** компьютера в разных внешних сетях, два синтетических аккаунта и действующий существующий Relay для регистрации/каталога. Две VM на одном хосте, два профиля в одном JVM, localhost, общая LAN и прямой IP между приложениями не заменяют этот стенд. Не использовать настоящие переписки, пароли, приватные identity/recovery/release-ключи или рабочий архив владельца.

## 2. Локальная диагностика kit

`VoiceNativeAcceptanceMain` — тестовый CLI из `aegis-native-tests.jar`, а не часть production JAR. По умолчанию он проверяет compiled pins комплектных аудиобиблиотек, перечисляет устройства и выполняет синтетический native Opus/Speex fixture. Устройства захвата/воспроизведения не открываются. Профиль АЕГИС, серверные настройки, ключи и переписки не читаются; сеть не используется.

Сначала распакуйте native kit и выберите каталог приложения, содержащий `runtime`, `app` и `native`. Для AppImage используйте его подготовленный распакованный AppDir по инструкции kit. Примеры запуска из отдельного каталога доказательств:

```powershell
$app = 'C:\AEGIS-Test\AEGIS'
$kit = 'C:\AEGIS-Test\native-kit'
& "$app\runtime\bin\java.exe" '-cp' "$kit\aegis-native-tests.jar;$app\app\*" 'org.securemail.client.security.VoiceNativeAcceptanceMain' $app '--output' 'voice-local-Windows.json'
```

```bash
app=/path/to/AEGIS.AppDir
kit=/path/to/native-kit
"$app/runtime/bin/java" -cp "$kit/aegis-native-tests.jar:$app/app/*" org.securemail.client.security.VoiceNativeAcceptanceMain "$app" --output voice-local-CachyOS.json
```

Только по явному решению оператора добавьте `--test-microphone`. Этот флаг открывает выбранный вход максимум на 15 секунд и собирает только локальные уровни. Для конкретного устройства можно добавить `--microphone-id 'ID из отчёта'`. Без флага ввод не открывается. Тест не воспроизводит и не отправляет звук, не создаёт аудиофайлов. Названия устройств попадают в локальный JSON; перед передачей отчёта проверьте их на личные названия Bluetooth-устройств. Отчёт не загружается автоматически, существующий файл не перезаписывается.

Даже при успехе локальных строк CLI сохраняет `nativeVoiceAcceptance`, `twoPhysicalMachinesOnDifferentNetworks`, `sixtyMinuteOnionCall`, `physicalPlaybackAndSpeechQuality` как `NOT_RUN`, а `productionReady` — `false`. Нулевой список устройств при успешном вызове API не доказывает наличие микрофона. Код завершения 0 относится только к выполненным локальным проверкам.

| L-02 | Явно запустить `--test-microphone`, говорить только тестовую фразу | Уровни > 0, правильный выбранный вход; без записи/передачи | NOT_RUN |

## 5. Два физических устройства, разные сети, ≥60 минут

Обязательны связки Windows 11 ↔ CachyOS KDE Wayland и Windows 11 ↔ CachyOS KDE X11. Для каждой — отдельный проход с реальным Tor. Системный Direct означает прямое подключение **Tor к его сети**, а не clearnet-сокет Гласа. Поддерживаемый Snowflake проверяется отдельным проходом/сценарием переключения, без изменения bridge-архитектуры.

До начала зафиксировать критерии разборчивости и допустимые задержки/нагрузку. Не выбирать пороги задним числом. Сохранить метод измерения, точность часов и погрешность. ICMP/TLS RTT, размер jitter buffer и субъективное ощущение сами по себе не измеряют задержку от микрофона до динамика.

|---|---|---|---|---|---|
| До звонка, baseline ≥30 с | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN |
| 1 минута | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN |

На протяжении часа вести двусторонний разговор тестовыми фразами, чередуя речь/тишину и корректно обозначая mute. Записать число неожиданных разрывов, их длительность и повторяемость, рост памяти, зависания и качество после паузы. По нагрузке учитывать JVM, Tor/PT, а при параллельном Взоре — его собственные Tor/браузер/VM отдельно. Суммарную CPU/RAM всей ОС не выдавать за стоимость Гласа.

Переход примерно на 60-й минуте намеренно создаёт свежий TLS-контекст через ограниченный reconnect. Проверить новый совпадающий короткий код при неизменном identity-отпечатке и повторно выключенные микрофоны. Включить их явно и продолжить ещё 5 минут. Ожидаемое отключение микрофона при этой операции не следует скрывать как «непрерывное автоматическое восстановление речи».

## 6. Сетевая проверка и приватность

Packet capture и системную привязку соединений к процессам выполняет оператор на собственных тестовых устройствах. Сначала снять baseline обычных сетевых служб; затем сопоставить JVM, messenger Tor, transport helpers и отдельный Взор. Сохранять чувствительный raw capture локально; для общего отчёта достаточно очищенной сводки и хэша доказательства. Не публиковать реальные IP, тестовые пароли, onion-каталог/переписки и ключи.

| ID | Реальное наблюдение | Статус |
|---|---|---|
| S-01 | JVM Гласа устанавливает только loopback SOCKS/локальный peer; отсутствует соединение к IP собеседника | NOT_RUN |
| S-02 | DNS имени peer не уходит от JVM в системный resolver; onion передаётся Tor как имя, а не разрешается локально | NOT_RUN |
| S-03 | От voice JVM нет UDP, ICE, STUN, TURN или WebRTC. Проверка включает начало, разговор, reconnect и отказ Tor | NOT_RUN |
| S-04 | При заблокированном/выключенном Tor отсутствует успешный прямой голос/сигнализация | NOT_RUN |
| S-05 | Transport TLS1.3/ALPN/пины и свежий код после reconnect подтверждены без вывода приватных ключей | NOT_RUN |
| S-06 | Поиск в диагностике не обнаруживает PCM/Opus, текста, identity private key, пароля, TLS/session secret или полного приватного URL | NOT_RUN |

Snowflake transport helper может использовать собственные механизмы WebRTC/UDP для связи Tor с мостом. Их нельзя автоматически объявлять голосовым WebRTC или DNS-утечкой JVM; нужна привязка к процессу и назначению. В Гласе нет своего WebRTC-медиа или UDP-сокета. Аналогично браузерный Tor Взора и системные службы не являются сокетами Гласа.

| U-04 | Намеренно вызвать сбой установки в тестовой копии: доказать rollback и повторный запуск предыдущей версии с сохранными данными | NOT_RUN |

Успешная проверка manifest не считается updater E2E. Не менять production Stable feed, pinned public key, production Relay или release private key. Подписывает только владелец на своём офлайн-устройстве.

## 9. Фиксация результата

Для каждой выполненной строки записать actual build/commit, UTC, стенд A/B, точные шаги, PASS/FAIL/NOT_RUN, краткое наблюдение, ограничения, путь/хэш реального доказательства и ответственное лицо. Скриншоты должны быть сняты с приложения на указанной платформе; не использовать сгенерированные изображения. Синтетические GUI-сцены и искусственный аудиосигнал так и обозначать.

Изолированный JSON/лог, screenshot или pcapture не закрывает соседние пункты автоматически. Сводка обязана перечислить непроверенные платформы, ограничения Windows Sandbox, качество физического звука и все дефекты. После приёмки владелец отдельно решает вопрос офлайн-подписи и Stable; этот checklist не является разрешением на публикацию.
