# Миграция5.0.0 →6.0.0

Сначала создайте отдельную зашифрованную копию профиля и проверьте её прежней программой. Не проводите испытания отказов на единственном архиве. Схема переноса: snapshot → копирование → проверка identity/ключей/писем/контактов/архива/тем/настроек → атомарное переключение. Старый профиль остаётся до приёмки.

MailProfileMigration600 сохраняет существующую идентичность; Core не создаёт новый почтовый root key и не переносит его к себе. Core получает только публичные account/recovery keys и свой отдельный device key. Конфигурация переключается после семантических проверок. Неподдерживаемый внешний архив, небезопасные симлинки и размещение в видимых sandbox paths блокируют перенос вместо неполного успешного копирования.

Личный зашифрованный архив не превращается в Library cache и не индексируется новостным ИИ. Пользовательские настройки/темы и относительный порядок навигации сохраняются. Core/Glas ключи не копируются обратно в Почту.

При ошибке до переключения источник остаётся действующим. Повтор проверяет уже подготовленное состояние. UpdateProfileSnapshot восстанавливает именно существовавшие каталоги: отсутствовавшие до снимка назначения не создаются. Legacy500Rollback600Test реально открывает восстановленный снимок точным опубликованным5 JAR; это локальная проверка совместимости, не полный нативный updater.

Для потери доверенного устройства нужны Mail identity backup и независимый `.aer6`. Оба private key остаются в Почте. Core сохраняет новый device key до изменения доверия сервера; неверный recovery proof отвергается. После успеха отзываются прежние поколения, а закрытые полномочия требуют независимой административной проверки. Исправление публичной recovery metadata оставляет предыдущий encrypted device vault и не меняет device private key. Power-loss/fsync fault injection отдельно не выполнен.

Старые5 клиенты продолжают совместимые операции прежнего Relay; расширения6 используют отдельные согласованные возможности. Поддержка5 заявлена минимум12 месяцев после фактического выпуска6. Legacy вход на уже enrolled6 identity запрещён по безопасности; для него нужна явная миграция/новый допуск, а не скрытый fallback.

Откат программы не удаляет новые данные и не гарантирует их чтение старой версией. После новых записей выбирайте согласованный снимок с учётом последующих изменений. На Windows явный возврат программы выполняет Core после остановки управляемых компонентов. Взор и личный Obsidian закройте отдельно; guard запрещает замену занятого runtime.

Полный Windows/CachyOS цикл install/migrate/restart/failure/rollback и серверное аварийное восстановление требуют целевой приёмки, даже если локальные миграционные тесты прошли.
