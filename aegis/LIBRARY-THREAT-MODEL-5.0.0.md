# Модель угроз общей библиотеки АЕГИС 5.0.0

## Активы и доверие

Защищаемые активы: закрытые материалы и их существование, вложения, поисковые результаты, названия и связи графа, версии, допуски пользователей, локальный кэш и identity клиента. Личный зашифрованный архив расположен за отдельной границей и не является источником общей библиотеки.

Доверенные компоненты: текущий код сервера авторизации, проверенная конфигурация ролей и идентичностей, закреплённый ключ общего сервера, существующие криптографические компоненты LocalStore. Сервер общей библиотеки видит её открытое содержимое в рамках серверной модели хранения. Это не E2EE-система общей библиотеки. Tor защищает сетевой маршрут клиента, но не скрывает от общего сервера его запросы и серверную identity.

## Угрозы и меры

| Угроза | Принудительная мера | Предел |
| --- | --- | --- |
| Подмена клиента/сервера | Ed25519-конверт точных HTTP-байтов, audience, nonce, проверенный ключ сервера, Tor onion | Компрометация конечного устройства или доверенного сервера выходит за эту гарантию |
| IDOR и обход через файл | `visible` проверяет материал и его текущую policy при каждом get/download/export | Уже экспортированный файл нельзя гарантированно отозвать |
| Повышение допуска | Серверные роли, уровень AND дополнительные права, отсутствие доверия клиентским флагам | Ошибочное санкционированное назначение роли остаётся административным риском |
| Утечка графа/поиска | Фильтрация до выдачи; обе вершины связи должны быть разрешены; нет общего закрытого счётчика | Тайминги запросов не заявляются как криптографически постоянные |
| Устаревшая роль | Проверка ACL в той же транзакции; epoch и повторная проверка перед ответом | Отключённая ранее разрешённая копия живёт в пределах офлайн-политики |
| Изменение без публикации | Независимые CREATE/EDIT/PUBLISH/ACCESS_MANAGE; вложения только в черновике | Уполномоченный издатель может публиковать ложный текст; требуется редакционная ответственность |
| Потеря редакции | Ожидаемый revision, сериализованная SQLite-транзакция, новая версия при восстановлении | Подтверждённое удаление/повреждение администратором ОС требует внешней резервной копии |
| Вредоносный HTML/JS | Инертный Markdown и JavaFX TextFlow, без исполнения WebView; никакой автоматической загрузки внешних изображений | Ошибка стороннего клиента может нарушить это требование |
| Файл-бомба/обход пути | 4 МиБ, 32 файла / 32 МиБ, MIME+magic, предел пикселей, случайный ID и SQLite BLOB | Сигнатура файла не доказывает отсутствие вредоносного содержимого |
| Уязвимый PDF/медиапарсер | Сервер не исполняет и не автодекодирует документы; экспорт — явное действие | Внешнее приложение просмотра может быть уязвимо |
| Prompt injection | Только явно разрешённые документы, локальная модель, ограниченные JSON-связи, без инструментов/секретов, редакторское подтверждение | Модель может предложить неверную связь; это не факт до проверки |
| Утечка в облачную модель | Закрытая библиотека направляется только разрешённому loopback-local adapter | Скомпрометированная локальная модель/ОС может утечь сама; администратор должен контролировать её |
| Кража локальных файлов | AEAD LocalStore sidecar, лимит и TTL; выход очищает кэш | Разблокированная память и заражённое устройство остаются уязвимыми |
| Подмена JSON/DoS | Строгий UTF-8, запрет дубликатов, ограничение глубины/узлов/строк/байтов, ограниченные ответы | Общая защита от распределённого сетевого DoS требует инфраструктуры |

## Отзыв и офлайн-доступ

Сервер прекращает новые выдачи после отзыва полномочий. Авторизация и операция выполняются одной транзакцией, включая запросы к вложенным ресурсам. Клиент инвалидирует кэш по актуальному epoch или подписанному отказу. Офлайн-копия допускается только при явном флаге материала и не более пяти минут.

Не заявляется удаление чужого файла после экспорта, уничтожение ранее сфотографированного экрана или защита от вредоносного ядра/драйвера. Очистка Java-объектов и временных массивов снижает время хранения, но не гарантирует стирание всех копий из памяти JVM.

## Доказательства и незавершённая приёмка

Воспроизводимые автоматические сценарии находятся в ContentServiceTest, CommunityJsonTest и CommunityClientTest. Они проверяют настоящую SQLite, production ACL, реальное шифрование LocalStore и подписанные локальные HTTP-пакеты. Сетевой fixture обозначен как локальный; он не подменяет проверку Tor или двух физических устройств.

Нативные Windows 11, CachyOS Wayland/X11, измерения разных сетей, проверка реальных политик ОС и полный updater E2E требуют отдельной приёмки готовых артефактов. До обязательных подтверждений общий release gate остаётся закрытым. Административные роли не дают обходить содержательную политику закрытого документа сами по себе.
