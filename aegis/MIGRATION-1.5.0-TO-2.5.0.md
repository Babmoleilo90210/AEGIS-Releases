# Миграция 1.5.0 Stable → 2.5.0

Используется существующий механизм полного снимка профиля до изменений новой версии. Криптографические алгоритмы писем/архива, identity и recovery keys не заменяются. См. также MIGRATION-2.0.0-TO-2.5.0.md: порядок резервирования и восстановления одинаков.

Старый шестисекционный порядок сохраняет все выбранные пользователем позиции. Взор (`safeweb`) добавляется перед настройками при отсутствии, Глас (`glas`) рядом с Взором. Существующие семь/восемь разделов читаются идемпотентно. Все 16 пресетов, дополнительные legacy-темы и пользовательские цвета остаются доступны.

Перед обновлением сделайте отдельную защищённую копию профиля, app-settings и самостоятельного архива. Не ограничивайтесь копией identity: она не содержит всех писем, вложений, настроек и archive location. Сохраните installer/portable 1.5.0 до завершения проверки. Не запускайте две версии на одном рабочем профиле одновременно.

Генератор manifest проверяет строгие требования старого SignedManifest: `tag == "v" + version`, все URL принадлежат тому же release tag, обязательные четыре артефакта, SHA-256 и объявление версии. Замороженные доступные исходники старых парсеров проверены отдельным тестом. Это не доказательство полного 1.5.0 updater E2E; старый release source неполон, provenance зависимостей frozen fixture указан явно.

Автоматические migration snapshots и fixtures не заменяют нативное обновление установленной 1.5.0 с загрузкой через Tor, установкой, перезапуском и rollback. Эти обязательные испытания пока NOT_RUN, `productionReady=false`.
