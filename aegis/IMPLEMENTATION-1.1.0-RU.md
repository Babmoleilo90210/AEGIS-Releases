# АЕГИС 1.1.0 — реализация

Рабочая ветка основана на исходниках 1.0.0 (SHA-256 исходного ZIP: 3745572f1261392a88b4ea4cfad7763d54e3fb9efb9a9d5a674eaa74abc5e2ee). Это продолжение проекта, не новая реализация.

## Авторитетные материалы

Открыты полностью технический аудит от 9 октября 2026, приложенные контрольные суммы, все JSON доказательства тестирования. Контрольные суммы отчёта и ZIP совпали, целостность ZIP проверена. Последнее сообщение владельца — утверждённое ТЗ. Оригиналы пяти этапов и отдельного итогового ТЗ из другого чата получить не удалось: три ограниченные попытки поиска вернули ошибку. Неизвестные уточнения нельзя считать изученными.

## Этапы

1. Восстановление контекста и фиксация основы.
2. BUG-02/05/06/08/09/10: безопасность аватаров, два Tor SOCKS-порта, независимая доставка неизвестных отправителей, реальная проверка запуска, полный backup, восстановление Control/P2P.
3. BUG-01/03/04/07: центральный профиль, собственные window controls, полное масштабирование, сохранение черновика.
4. Локальные избранное/блокировки/поиск/offline; ответы/цепочки/пересылка; настройки уведомлений.
5. Optional protocol-1 операции подписанных профилей и контактов; аддитивная миграция staging Relay; проверка старых клиентов.
6. Resume updater, регулярная проверка, подтверждение установки, полный backup и откат.
7. Сборка и unit/integration/security проверки; подготовка кандидатов ZIP/AppImage/Setup; нативная приёмка отдельной матрицей.

## Ограничения выпуска

productionReady=false. Production VPS, опубликованные релизы, production manifest и release signing keys не меняются. Onion identity и существующие crypto identity keys сохраняются. Никакой production подписи или публикации без владельца. Архивные 54/86 тестов не являются новой проверкой изменённого кода. Windows 11, KDE Wayland/X11 и реальный Tor E2E в этом окружении пока не проверены.

## Совместимость

Wire protocol остаётся 1. Существующие opcodes и формат vault не меняются; новые локальные данные — отдельный зашифрованный versioned sidecar. Relay расширяется optional операциями, capabilities определяются явно. При старом Relay базовая переписка работает, новые серверные функции отключены.

## Решения

Для GitHub updater используется второй SOCKS-порт собственного Tor (127.0.0.1:19052). Переписка сохраняет 127.0.0.1:19050 OnionTrafficOnly. Ed25519 pinned public key сохраняется побайтно. Локальные plaintext сообщения, пароли и приватные ключи не передаются CI/Relay.

Первый переход 1.0.0 → 1.1.0 требует явно проверяемого установщика: старый updater несовместим с OnionTrafficOnly. Bootstrap, изменяющий пользовательский torrc, не исправляет архитектуру: EmbeddedTor снова переписывает его. Способ проверки первого установщика должен быть доказан до выпуска; автоматический переход 1.0.0 пока не подтверждён.
