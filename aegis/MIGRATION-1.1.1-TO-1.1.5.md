# Миграция 1.1.1 → 1.1.5

Relay менять не требуется. Не переносите onion secret keys и не создавайте новую identity.

Клиент добавляет отдельную папку `appearance` к существующему профилю. Старые `theme.txt` и `ui-preferences.json` сначала копируются в `appearance/migration-1.1.1`, затем новая схема сохраняется атомарно. Старые файлы не удаляются. Повторный запуск читает завершённый файл; повреждённая новая схема не вызывает разрушительную повторную миграцию. Неизвестные прежние значения дают читаемый fallback и диагностическое сообщение.

Сохранены названия прежних тем и тёмно-зелёная палитра. Масштаб, плотность, аватары, признаки списка, свёрнутый sidebar и предпросмотр снизу переносятся. Новые настройки локальные: их не синхронизирует Relay.

Updater перед заменой копирует ciphertext vault, identity, контакты, вложения, receipts/TTL и имеющиеся настройки/сессии/Tor state. В полный ProfileSnapshot добавлены appearance и локальная история update events. Lock и control cookie не копируются. Проверяется digest инвентаря. Ошибка запуска восстанавливает бинарники и совместимый snapshot; неудачное состояние сохраняется отдельным переименованием для диагностики.

**Ограничение исходной 1.1.1:** открытый черновик хранится в памяти, а не в зашифрованном файле. Визуальные изменения сохраняют его. Сохранность незавершённого черновика при завершении процесса не доказана; исходная логика очистки не изменена. Для постоянных зашифрованных черновиков понадобится отдельное решение о расширении локальных секретных данных. Нельзя объявлять весь migration gate пройденным по одной проверке оформления. Перед установкой завершите письмо или осознанно очистите черновик.

Безопасный ручной путь до подписанного feed: закрыть АЕГИС, сделать полный backup профиля, запустить Windows Setup под обычным пользователем либо заменить AppImage. Installer сохраняет `%LOCALAPPDATA%\AEGIS`; Linux сохраняет прежний профиль. Native acceptance kit проверяет это на копии тестового профиля.
