# АЕГИС 6.0.0 — нативная приёмка

Статус на 19 октября 2026 г.: обязательная приёмка итоговых бинарников не завершена. `productionReady=false`. Основание требований — мастер-задание «АЕГИС 6.0.0 — Экосистема», версия 18.10.2026, разделы 0, 17 и 19. Это журнал доступности и программа реальной приёмки, а не протокол успешного испытания.

## Фактически доступная среда

Восстановленная рабочая среда: Ubuntu 24.04.3 LTS, Linux x86_64, PID 1 — `supervisord`. Сохранён фактический результат в [ENVIRONMENT.json](docs/test-results/6.0.0/restoration-security/ENVIRONMENT.json). Пробный запуск `bwrap --unshare-all … /usr/bin/true` завершился кодом 1: создание `NETLINK_ROUTE` запрещено. `Xephyr`, `slirp4netns` и `adb` при этом обследовании отсутствовали. Это препятствие выполнения ОС-песочницы в данной среде, а не доказательство дефекта CachyOS или разрешение включить незащищённый запуск.

| Платформа/сценарий | Статус для итогового 6.0.0 | Основание |
|---|---|---|
| Windows 11 x64, поддерживаемые редакции с Windows Sandbox | NOT_RUN | Нет доступного Windows 11 |
| Windows 11 Home | BLOCKED | Испытанный альтернативный механизм изоляции не представлен; небезопасный fallback запрещён |
| CachyOS KDE Wayland | NOT_RUN | Ubuntu headless не является CachyOS KDE/Xwayland |
| CachyOS KDE X11 | NOT_RUN | Нет целевого графического окружения |
| Debian 13 staging, systemd/AppArmor | NOT_RUN | Нет Debian 13 с работающим целевым init и AppArmor |
| Android 13+ ARM64 | NOT_RUN | Нет физического устройства, USB/adb или подходящего эмулятора |
| Два физических устройства в независимых сетях | NOT_RUN | Локальные процессы и SOCKS-fixture этого условия не выполняют |
| Обновление с установкой, перезапуском и rollback | NOT_RUN | Проверки парсера/локального HTTP не заменяют полный сценарий на целевых ОС |

Сообщение владельца об испытаниях Windows/CachyOS предыдущей версии сохранено как историческое свидетельство. Оно не относится автоматически к новому commit, APK, EXE или AppImage. Для приёмки 6.0.0 требуется запись точных SHA-256 проверенных файлов, среды и фактически выполненных шагов. Повторного владельческого подписания в Work не требуется и не выполняется.

## Что проверяется на ПК

На каждой заявленной ОС установить точный кандидат и записать SHA-256. Проверить первоначальную конфигурацию pinned-ключей; регистрацию/вход/подтверждение нового устройства/восстановление; атомарный отзыв прежней сессии; 10-минутную и системную блокировку; предел offline-допуска и откат часов; согласованную работу Почты, контактов, архива, вложений 500 МиБ и Гласа.

Проверить реальные процессы: Core lock не открывает личные данные через экран входящего вызова; полный выход сохраняет очереди и завершает Почту/Глас/защищённый Obsidian; личный Obsidian и Взор остаются самостоятельными. Проверить невозможность подменить IPC, исполняемые файлы и управляющий канал, а также отказ запуска без действующих полномочий.

Для Взора проверить подлинность официального Tor Browser, установку/обновление, namespaces/VM, отсутствие доступа к Core/Mail/архиву, DNS/WebRTC/прямые соединения, HTTPS/onion, загрузки и независимый жизненный цикл. Для Obsidian проверить отдельные личный и защищённый профили, сохранение его штатного Chromium sandbox, запрет произвольных плагинов в защищённом профиле, ровно одну разрешённую проекцию и закрытие при отзыве/истечении допуска. Наблюдение одного открывшегося окна не является проверкой изоляции.

Визуальная матрица: все основные экраны, длинные русские подписи, 800×600/1024×768/1366×768/1920×1080/максимизация, 100/125/150/200%, 16 пресетов и пользовательская тема. JavaFX Monocle и сохранённые PNG — полезные headless-регрессии, а не нативный PASS.

## Что проверяется на Android

Установить четыре APK с одним явно проверенным сертификатом; отдельные package ID/UID, без sharedUserId. Проверить Binder-подмену UID/package/certificate, повтор nonce/старого поколения, узкие разрешения, отзыв при входе на другом устройстве. Проверить `FLAG_SECURE`, миниатюры, диалоги и опасные наложения на реальном Android.

Проверить AudioRecord/AudioTrack и JNI на ARM64, отсутствие захвата до принятия и криптографической аутентификации, mute/устройства/ошибки/остановку, входящий экран при системной блокировке. Реальный Tor-звонок измерить на двух устройствах и независимых сетях; отметить задержку, длительность и нагрузку. Искусственный PCM и локальный TLS не заменяют акустический/сетевой прогон.

Проверить фактическое `VpnService.protect`, DNS, IPv4/IPv6, сетевые петли, смену сети, Always-on/lockdown, прямой fallback, ограничения UDP. Отдельно — Doze, App Standby, foreground-service notification, battery saver, остановку процесса и полный выход. Нельзя обещать мгновенные входящие звонки при остановленной службе.

Выпускные APK подписывает владелец отдельно от Ed25519 manifest key. Проверить первую установку по независимому отпечатку, обновление и разрешённую ротацию сертификата; TEST-сертификат не объявляется производственным.

## Сервер, безопасность и результаты

Debian staging должен проверить sysusers, ACL/владение каталогами, systemd/AppArmor, ограничения памяти/диска/процессов, onion endpoints, отделение служебных ключей, восстановление зашифрованной внешней копии и аварийное восстановление. Деструктивные проверки выполняются на тестовой копии, а не production VPS.

Сохранять для каждого прогона: ID сценария, PASS/FAIL/BLOCKED/NOT_RUN (либо SKIPPED с причиной), дату, команду/шаги, ОС и редакцию, точный commit/tree, SHA-256 бинарников, журналы/снимки без секретов и ограничения. BLOCKED, NOT_RUN и SKIPPED никогда не превращаются в PASS из-за прошедшего времени.

Машинная проверка согласованности:

```bash
python3 tools/evaluate-release-gates600.py RELEASE-GATES-6.0.0.json --evidence-root .
```

Код возврата 2 означает корректно записанную неготовность; 1 — несогласованное/повреждённое свидетельство; 0 допустим лишь после прохождения полного набора обязательных gates. Это не выдаёт разрешение на публикацию и не заменяет независимую приёмку.
