# Проверки АЕГИС 1.1.0

Кандидат; productionReady=false. Архивные 54 теста 1.0.0 и 16 release/security tests изучены, но не выдаются за проверку нового клиента. Изменённые исходники собираются на Java 21.

Текущие JUnit XML: 101 тестов; 100 PASS, 1 Windows DPAPI SKIP в Linux. Отдельные 16 Python release/security tests PASS. JavaFX Monocle проверяет всю геометрию Scene на 80/100/125/150/200%, сохранение масштаба, черновиков и файлов, центральный профиль и неизменяемый nickname, масштаб диалогов и один window chrome. Compatibility matrix: выпущенный client-core 1.0.0 → независимо собранный Relay 0.2.0, 1.0.0 → 0.3.0, 1.1.0 → 0.2.0 — PASS. Подтверждены двусторонние защищённые письма, offline, 7 типов вложений, AES ZIP, ACK, replay/dedup, TTL и перезапуск процессов. К одной SQLite применена 0.2 → 0.3 миграция: хеши строк users/mailbox/receipts не изменились. Старый Relay повторно открыл мигрированную БД и доставил обычное письмо. Опубликованный серверный бинарник не выдаётся за проверенный: Relay 0.2.0 для матрицы компилируется из проверенного архива исходников.

Отдельно проверен отзыв friendship consent после удаления контакта offline и повторной авторизации. Состояние отзыва хранится зашифрованно и синхронизируется даже после удаления контакта. Скрытие профиля распространяется при следующем online sync; оно не уничтожает чужие уже сделанные копии.

Нативная приёмка Windows 11, KDE Wayland/X11, live Tor Direct/Snowflake, внешний Relay и reboot, установщик/restart/rollback — NOT RUN. Монокль, loopback SOCKS harness и Linux CI не считаются этими проверками. Проверки staging используют синтетические аккаунты и временную SQLite; production VPS не затронут.

Проверен реальный bundled Linux Tor lifecycle с ограниченным временем: собственный torrc и DataDirectory с пробелами, отдельные mail/update SOCKS, автоматический Snowflake и запуск настоящего Lyrebird, сохранность постороннего процесса Tor и освобождение трёх портов. Bootstrap успел дойти только до 10%; public Tor 100% и реальный обмен не заявлены.

Упаковка обнаружила несовместимость xz SquashFS с проверенным runtime AppImage (поддерживает zlib/zstd). Упаковщик использует zstd и проверяет действительное извлечение каждого файла; простое успешное создание SquashFS не считается корректным AppImage.

Full snapshot дополнен signed updater history/floors/announcement metadata без копирования активных updater jobs/cache. Даже уже modern vault 1.0 получает полный первый snapshot перед 1.1 sidecars. Проверено восстановление удалённого файла metadata, исходного floor и неизменность identity.

Также отклоняется корректно подписанный чужой аватар с недопустимыми размерами до декодирования пикселей и записи cache. Display проходит тот же ограниченный декодер: подпись подтверждает владельца, но не безопасность изображения. Неверный аватар не должен обнулить страницу остальных контактов.

Корректная подпись неизвестного отправителя при повреждённом AEAD ciphertext не подавляет остальные результаты входящих: письмо отмечено как повреждённое, второе остаётся доступным. Подпись отправителя и целостность содержимого не смешиваются.
