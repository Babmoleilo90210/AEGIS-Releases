# Переход АЕГИС 1.2.0 → 1.5.0

Protocol1, message crypto, identity и основной vault формат не меняются. Новый архив отдельный: не создаётся до действия пользователя и не импортирует письма автоматически. Прежние письма не получают новые TTL/receipts.

1. Закройте1.2, сохраните полный профиль и текущую программу на локальном защищённом диске. Identity backup недостаточен: нужны письма, ciphertext attachments/lifecycle, contacts, settings/themes/layouts, Tor state, session и update history.
2. Установите проверенные итоговые бинарники1.5.0. Перед изменением sidecars `ClientUpgrade.beforeVersionOpen("1.5.0")` создаёт полный ciphertext/settings snapshot и проверяет digest. Marker делает операцию повторяемой; повреждённый snapshot останавливает переход.
3. Старый порядок навигации сопоставляется с новым. Default становится Поиск/Профиль/Контакты/Письма/Архив/Настройки; пользовательский порядок сохраняется, Friends скрывается, Архив добавляется после Писем. Все темы/палитры/макеты/шрифты сохраняются. Исходный appearance backup остаётся.
4. Archive UI preferences и route evidence — новые AEAD sidecars в vault; существующие packet/salt/state/lifecycle formats не заменяются. RekeyCopy умеет сохранить новые sidecars. Полнотекстовый архивный индекс существует только внутри отдельного encrypted контейнера.
5. Перед updater main waits архивного worker, helper ждёт завершения основного PID/launcher, затем snapshot включает управляемый .personal-archive и restored/diagnostic siblings. Папки резервных копий архива и выбранные внешние контейнеры не переписываются миграцией; храните их собственные encrypted backups отдельно.
6. При провале startup health проверок прежние бинарники и совместимое состояние восстанавливаются штатным updater. Guard архива не откатывается: до успешного startup ACK нельзя выполнять архивные записи. Если после подтверждения пользователь менял архив, ручной возврат старого container требует восстановления над копией.

Manual запуск старого1.2 поверх нового appearance может включить его safe appearance fallback; старый бинарник нельзя ретроактивно заставить понимать новый раздел. Для ручного отката восстановите version-specific snapshot вместе с предыдущей программой. Никакие ключи ради архива не заменяются. Windows11/KDE и owner-signed E2E ещё должны подтвердить эту процедуру на пользовательской системе.
