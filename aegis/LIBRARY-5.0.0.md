# Общая библиотека АЕГИС 5.0.0

## Назначение

Библиотека — серверная система разрешённых общих материалов. Она не читает и не перемещает документы личного зашифрованного архива. Для неё не используются архивный пароль, recovery key или ключ шифрования архива.

Материалы представлены типами NOTE, ARTICLE, DOCUMENT, PDF, IMAGE, VIDEO, NEWS, EVENT, PERSON, ORGANIZATION, TOPIC. Типы отображаются русскими названиями. Вложения используют единое серверное файловое хранилище с актуальной проверкой политики родительского материала. Нет автоматического импорта приватных документов.

## Компоновка

Слева находится дерево материалов, в центре граф, справа выбранный документ. На узком окне SplitPane перестраивается вертикально. Доступен обычный список. Граф поддерживает выбор, перетаскивание узлов, перемещение, масштабирование и подсветку связей; материалы загружаются страницами, а не всем хранилищем сразу.

Фильтры включают строку поиска, тип, организацию и дату. Результат выдаёт только доступные узлы. Сервер не возвращает имена, связи или общие количества закрытых объектов. Любая связь выдаётся лишь после проверки обеих вершин. Сохранение представления не меняет права доступа к данным.

## Работа с документом

Канонический источник — Markdown. Визуальный режим предоставляет изменение блоков и добавление абзацев, заголовков, списков, таблиц, цитат и ссылок. Режим Markdown открывает исходник. Переключение сохраняет исходное содержимое; сервер также сохраняет начальные и конечные пробелы текста.

Предпросмотр построен из JavaFX Text/TextFlow и контролов. JavaScript, HTML-движок и JavaFX WebView не используются для выполнения документов. Внешняя ссылка открывается только после явного действия через безопасный URL-путь «Взора». Изображение в Markdown не создаёт автоматический прямой запрос к внешнему сайту. Текст недоверенного HTML показывается как данные.

Создание, изменение, публикация, модерация, экспорт и удаление — отдельные серверные разрешения. Чтение не даёт право редактирования. Пользователь без роли может читать разрешённый общий материал; закрытый документ требует выполнения всех условий policy.

Каждая запись имеет `revision`. Сохранение со старым номером возвращает CONFLICT вместо незаметной потери чужих изменений. История сохраняет текст, редактора и время; её содержимое доступно только текущему редактору. Восстановление создаёт новую редакцию, сохраняя действующую политику доступа.

## Связи и ИИ

Предложение связи хранит две существующие вершины, объяснение, состояние и происхождение AI. PROPOSED не превращается в постоянную связь автоматически. Подтверждение требует LIBRARY_EDIT в областях обеих вершин и текущего права чтения. Отклонение также проверяет редакторские полномочия.

Предложения доступны только читателям обеих вершин. AI-предложение создаётся внутренним `proposeAi`, а обычный клиент не может присвоить себе AI-флаг. LocalLibraryLinks получает материалы через текущий ACL пользователя, передаёт ограниченный текст разрешённой локальной модели и перед сохранением повторно проверяет допуск и версии. Закрытые материалы не направляются публичным новостным рабочим узлам или внешнему API модели.

Граф возвращает до 100 узлов с динамическим ограничением 7000 JSON values / 7 МиБ под пределы production-декодеров. Рёбра между страницами сохраняются: связь выдаётся при достижении большего ID концов, а непрозрачный `nextCursor` при необходимости продолжает рёбра одного узла. Такой узел может повториться; клиент объединяет узлы по ID. Оба конца каждой связи проходят текущие ACL и фильтры, закрытые названия/ID не попадают в cursor. Dense SQLite regression получает все 64 узла и 2016 рёбер через строгий JSON decoder без потери и повторения связей. Детальные связи выбранного узла также выдаются ACL-фильтрованным `content.library.link.list`.

## Зашифрованный кэш

Клиент хранит разрешённые офлайн-копии в собственной версии расширения LocalStore `community-v1`, защищённой существующим AEAD-профилем. Это отдельный sidecar; данные не помещаются в личный архив и не используют его ключ.

Офлайн-кэш создаётся только для ответов get с `policy.offlineAllowed=true`. Лимит — 3 МиБ / 100 записей; срок — не более пяти минут. Ответ с новым authorization epoch инвалидирует старый кэш, подписанный отказ очищает его, выход очищает копии. Смена доверенного сервера не переносит старые разрешения. Повреждение дополнительного кэша блокирует общую систему до повторной настройки, сохраняя identity и остальные функции аккаунта.

Серверный отзыв не способен гарантированно удалить ранее сохранённый или экспортированный документ с отключённого устройства. В пределах допустимого офлайн-срока пользователь может иметь ранее разрешённую копию; интерфейс помечает её как офлайн-копию.

## Проверки

Серверные JUnit проверяют скрытые узлы/связи, вложенный файловый IDOR, экспорт, отзыв допуска, разграничение чтения/изменения, конфликт двух редакторов, восстановление редакций, типы, пагинацию и реальные данные SQLite после перезапуска.

Клиентские JUnit используют production LocalStore и реальные локальные HTTP-сокеты с Ed25519-конвертами. Проверены отсутствие открытого кэша на диске, ограничение срока, изменение epoch, отказ сервера, подмена ответа, повреждённый кэш и сохранение identity после перезапуска. Это не доказательство нативной работы Windows/CachyOS или Tor-сети; соответствующие результаты находятся в общей матрице приёмки.
