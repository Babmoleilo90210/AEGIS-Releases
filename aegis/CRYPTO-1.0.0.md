# Защищённые письма АЕГИС 1.0.0

Клиенты обновлены, сервер 0.2.0 и protocol 1 остаются прежними. Новое содержимое v4 (с прежним letter envelope v3) находится внутри существующего непрозрачного E2EE-конверта. Relay не подключает client-core.

## Секреты

Пароль аккаунта проверяет relay. Тот же введённый пароль открывает vault с независимым KDF context; старый отдельный пароль нужен один раз при миграции. Пароль письма и код второго слоя задаются заново для каждого письма и используются только локально. Нет мастер-ключа и восстановления забытого пароля письма.

Текст UTF-8 преобразуется в последовательность цифр radix 16, шифруется стандартным FF1 из Bouncy Castle 1.86, затем внешним AES-256-GCM, затем существующим AutomaticEncryption. Реализация FF1 использует AES, не собственный шифр. Для текстов короче трёх байтов применяется нулевое дополнение до трёх байтов; исходная длина хранится внутри аутентифицированного слоя. Домен даже короткого текста: 16^6 = 16 777 216. Текст ограничен 64 KiB.

Две независимые Argon2id derivation: v19, 64 MiB, 3 прохода, 1 lane, 32 байта. Каждый слой имеет случайную соль 16 байтов и отдельное domain separation значение в Argon2 additional data. FF1 имеет случайный tweak 16 байтов. AES имеет свежий nonce 12 байтов и тег 16 байтов. Идентификатор схемы, соль и nonce включены в AES AAD. Параметры фиксированы и версионируются вместе с локальным содержимым.

Пароль письма при создании: 8–1024 символов. Код: 1–1024 символа. Это технические границы, а не рекомендация выбирать короткие секреты. Используйте независимые длинные случайные секреты. Код не выводится из пароля, имени или правил приложения.

## Открытие

Сначала AES-GCM полностью проверяет подлинность. Ошибка не показывает внутренние данные. После успешного AES видны цифры FF1. Ввод кода через 100 ms запускает Argon2id и FF1 в отдельном потоке. Предыдущий результат очищается сразу; завершение устаревшего задания не может заменить новый результат. Одновременно выполняется одна KDF и ожидает не более одного задания.

Внутри FF1 намеренно нет тега, контрольной суммы или признака «правильный код». Любой код выдаёт кандидат. Валидные UTF-8 байты показываются как текст, остальные — как hex. Это выбор представления, не проверка кода. Для пустого поля виден исходный FF1 ciphertext.

FF1 не обеспечивает deniable encryption: узнаваемость текста, длина, UTF-8 структура и известный текст могут помогать перебору. Внешний AES тег также позволяет проверять догадки о пароле, если атакующий получил внутренний конверт. Argon2id замедляет перебор, но слабые секреты не спасает.

## Вложения и совместимость

Файл целиком защищён существующим E2EE, вместе с именем и темой. Дополнительные пароль письма и код защищают **текст**, а не вложение. GUI разрешает скачать вложения после проверки пароля письма, в один AES ZIP с этим же паролем. Это ограничение интерфейса: сами переданные файлы имеют слой E2EE, а не дополнительный парольный слой.

Новые клиенты открывают старое содержимое v1 и сообщения прежних ручных режимов 0.1.0. Клиенты 0.2/0.3 не умеют отображать новое содержимое v4: обоим участникам новых писем нужен 1.0.0. Relay менять не нужно.

Существующий E2EE использует AES-GCM и libsodium sealed boxes с Ed25519 идентичностями; forward secrecy отсутствует. Компрометация приватной идентичности может раскрыть сохранённый E2EE слой, включая тему и файлы. Два секрета текста всё ещё нужны для нового тела письма. Компрометированная ОС может перехватить их при вводе.

## Источники

- [Bouncy Castle FPEFF1Engine](https://downloads.bouncycastle.org/java/docs/bcprov-jdk18on-javadoc/org/bouncycastle/crypto/fpe/FPEFF1Engine.html)
- [NIST SP 800-38G](https://csrc.nist.gov/pubs/sp/800/38/g/final)
- [NIST revision 1, второй публичный проект 2025 года](https://csrc.nist.gov/pubs/sp/800/38/g/r1/2pd): более строгий минимальный домен. Проект не объявляется финальным стандартом.
- [RFC 9106 Argon2](https://www.rfc-editor.org/rfc/rfc9106)
- [libsodium sealed boxes](https://doc.libsodium.org/public-key_cryptography/sealed_boxes)

Известный NIST vector FF1 (AES-128, radix 10, пустой tweak): 0123456789 → 2433477484 проверен тестом. Производственная схема FF1 использует производный AES-256 ключ.


## Vault и ZIP 1.0

Новый vault Argon2id использует отдельную соль16 и Additional=AEGIS-VAULT-v1, остальные параметры прежние. Legacy vault открывается прежним KDF и полностью rekey после relay auth; см. MIGRATION-0.3-TO-1.0.md.

Несколько файлов входят в content v4 внутри неизменённого E2EE. Экспорт: Zip4j2.11.6, AES256 AE2, password ровно letter password, UTF8, DEFLATE. Совместимый ZIP KDF слабее Argon2id, headers открыты; см. SECURITY.md.
