# АЕГИС 0.3.0

Обновление только клиентов. Debian relay 0.2.0, common-protocol, protocol 1, конфигурация регистрации, SQLite и onion identity не изменены.

- Почтовые разделы: Входящие, Отправленные, Новое письмо, Контакты, Настройки.
- Тема и два независимых секрета для каждого нового письма; FF1 → AES-256-GCM → существующий E2EE.
- Ввод кода прямо в открытом письме, автоматический пересчёт, подавление устаревших результатов.
- Одинаковое повторное открытие отправленного и полученного письма; секреты не запоминаются.
- Пять тем с немедленным применением.
- Автоматическое direct Tor timeout → закрытие собственного процесса → свежий Snowflake процесс. Убран ненадёжный диалог fallback.
- Исправлены буквальные кавычки в Tor exec path: Lyrebird запускается отдельно по абсолютному пути с PT-v1 negotiation и объявляет loopback SOCKS5 endpoint.
- Исправлены отсутствовавшие execute permissions Linux Lyrebird в прежнем AppImage.
- Проверяется реальный bootstrap и SOCKS, а не фиксированная пауза.
- Завершение собственного Tor и его transport descendants, без глобального taskkill.
- Ограниченный локальный журнал технических событий.
- Настоящий NSIS Setup, установка текущему пользователю, ярлыки, сохранение профиля при удалении.
- Старый vault v1 не мигрирует; до первого открытия создана зашифрованная резервная копия идентичности.
- Индекс списка писем не удерживает все вложения в памяти.
- Старые сообщения, контакты, резервные копии, P2P, offline relay, ACK и TTL сохранены.

Обнаруженные ограничения исходной 0.2.0: UI fallback зависел от modal Yes/No; не было полноценного installer; история могла удерживать все ciphertext packets; не было нового почтового content v3. Ни одна серверная ошибка из старой установки не исправляется изменением уже установленного сервера в этом клиентском релизе.

Известные ограничения 0.3.0: нет forward secrecy; вложения не защищаются двумя дополнительными секретами текста; relay wire 1 не сообщает отправителю offline ACK, поэтому статус отправленной копии остаётся честно «подтверждение недоступно». Native Windows 11, чистая CachyOS и реальный cross-network Tor acceptance требуют отдельной приёмки; выполненные проверки перечислены в отчёте.
