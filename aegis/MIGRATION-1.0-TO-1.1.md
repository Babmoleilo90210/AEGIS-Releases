# Переход 1.0.0 → 1.1.0

## Выбор первого перехода

Выбран проверяемый установщик Windows и явная замена AppImage на CachyOS. Старый updater использует onion-only SOCKS для GitHub HTTPS; нельзя рассчитывать на автоматический первый переход. Bootstrap, просто исправляющий torrc, ненадёжен: 1.0.0 снова генерирует torrc при запуске. Отдельный bootstrap с собственным Tor расширяет доверенную поверхность и дублирует новый updater.

Перед первым переходом проверить подпись manifest независимой доверенной копией pinned public key, затем SHA-256 и размер скачанного пакета. Самопроверка скачанного EXE не является независимым доказательством его происхождения. Для обычного распространения владелец публикует manifest и подпись вместе с релизом после нативной приёмки. Сейчас подписи production нет.

На CachyOS: `python3 tools/verify-release-manifest updates/stable.json updates/stable.json.sig --assets . --minimum-version 1.0.0`. Команда только проверяет; ключ владельца не нужен. Для Windows можно использовать ту же независимую проверку на доверенном компьютере и перенести проверенный пакет. Новый updater работает из приложения после подтверждённой установки 1.1.0.

## Сохранность

Installer не удаляет `%LOCALAPPDATA%\AEGIS`. Linux использует существующие XDG пути. До миграции и установки создаётся полный ciphertext/settings snapshot с inventory SHA-256. Предыдущие бинарные файлы сохраняются для отката. Миграция прежнего vault сохраняет identity, контакты, письма, время получения, TTL и receipts; дополнительные данные 1.1 находятся в отдельном зашифрованном sidecar. Plaintext staging не создаётся.

Системные ключи Windows DPAPI/Linux Secret Service переносимы только в пределах возможностей ОС. Для входа на другом компьютере нужен пароль хранилища; identity export не заменяет весь профиль. Семидневное локальное разблокирование сохранено. Production Relay 0.2.0 имеет 12-часовой bearer token в RAM: после его истечения или перезапуска Relay нужно заново войти в сеть по паролю. Этот предел не скрывается под обещанием семидневной сетевой сессии.

Обычные одиночные письма остаются в старом формате. Структурированные ответы/пересылки и несколько обычных вложений используют content v5 после подтверждения подписанного профиля получателя 1.1. Не следует запускать старый клиент для той же identity после включения таких функций: 1.0 не читает v5; сохраняется поддержка обычной переписки между отдельными 1.0/1.1 аккаунтами. Полный downgrade после получения v5 требует полного snapshot, а не только замены EXE.

У старых локальных подстановок чужих аватаров нет подписи владельца. Они не применяются в 1.1; прежний профиль/snapshot сохраняет их для аудита. Собственный аватар сохраняется.

## Границы отката

Updater ждёт подтверждения открытого vault и основного окна до 10 минут; до этого получения/ACK новых писем нет. При ошибке остановлены только запущенные helper процессы, возвращаются прежние бинарные файлы и проверенное состояние профиля. Если файловая система/права мешают автоматическому восстановлению, сохранённые `.old`, snapshot и `.failed-update-*` используются для ручного восстановления. Не обещается откат при уничтожении диска или несовместимой защите ОС. Нативный цикл updater ещё требует приёмки.
