# Архитектура 0.2.0

Два независимых приложения используют common-protocol. Relay загружает только общие модели, SQLite и password hashing. Он проверяет Ed25519-подписи публичными ключами; кода расшифровки содержимого в его classpath нет. Gradle verifyIsolation проверяет это разделение.

Клиент: GUI → PlainMessage в RAM → AutomaticEncryption → EncryptedPacket → NetworkService. Публичный метод отправки принимает EncryptedPacket. Ручной EncryptionService для пяти прежних алгоритмов находится только в client-core.

При входе ClientSession открывает зашифрованный LocalStore, аутентифицируется на relay и поднимает PeerServer на loopback. SAFECOOKIE TorControl создаёт временный v3 onion без возврата приватного onion-ключа. Подписанный маршрут живёт ограниченное время и обновляется. Если P2P отвечает подписанным ACK, STORE на relay не выполняется. Иначе тот же messageId уходит в offline mailbox.

FETCH не удаляет запись. LocalStore проверяет подпись и закреплённый ключ отправителя, сохраняет ciphertext атомарно, фиксирует первое время приёма и dedup state. Затем клиент передаёт ACK. Повторная доставка возвращает тот же receipt. Relay сохраняет минимальный receipt tombstone до delivery deadline, чтобы ACK-потеря не создала дубликат.

Vault и контакты остаются в state.vault v1. Полученные письма сохраняются в mail/*.sm. Новый sent/*.sm содержит исходящий EncryptedPacket и локальный статус, дополнительно защищённые vault-ключом; plaintext истории на диске нет. UI расшифровывает видимый чат в RAM и удаляет истёкшие bubbles.

Tor запускается дочерним процессом из абсолютного пути пакета. Используются собственные defaults-torrc и torrc, bootstrap проверяется по аутентифицированному control protocol и SOCKS greeting. Профиль заблокирован file lock. Windows launcher дополнительно использует Job Object. Приложение не присоединяется к случайному процессу, занявшему порт.

Регистрация сначала создаёт зашифрованную временную идентичность. Явный отказ REGISTER позволяет удалить новый staging-профиль. Неоднозначный сетевой результат сохраняет идентичность и переключает конфиг на неё, чтобы можно было войти, если сервер уже принял REGISTER. Идентичность, которую сервер мог зарегистрировать, не уничтожается автоматически.

JavaFX работает на UI thread; сеть, Argon2 и шифрование выполняются в background executor. Временная блокировка относится к кнопке; finally возвращает её состояние. Диагностика отделена от обычного чата.
