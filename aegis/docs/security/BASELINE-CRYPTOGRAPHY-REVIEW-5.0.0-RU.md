# Обзор сохранённой криптографической базы АЕГИС 5.0.0

Область этого обзора — чтение текущих исходников `AutomaticEncryption`, `EncryptionService`, `Secrets`, `Identity`, `SodiumBox`, голосовых сервисов, `TorTransport`, технического журналирования, голосовой миграции и нового HTTP-контекста. Это ограниченный инженерный обзор и воспроизводимые тесты, а не формальная криптографическая верификация, внешний penetration test или актуальный полный CVE-анализ зависимостей. Алгоритмы и формат ранее сохранённых писем/архива из-за этого обзора не заменялись.

## Подтверждённые свойства и границы

| Компонент | Что следует из исходников | Ограничение |
|---|---|---|
| Автоматическая E2EE-переписка | Для сообщения создаются новый 256-битный ключ AES-GCM и случайный nonce; ключ оборачивается sealed boxes для получателя и отправителя; подпись Ed25519 проверяется до открытия содержимого, а заголовки входят в подписанный/аутентифицированный контекст | **Forward Secrecy писем нет**: сохранённый пакет может открываться после кражи соответствующей долговременной private identity. Это уже указано в `SECURITY.md`, `THREAT_MODEL.md`, `CRYPTO-1.0.0.md`. Свойства TLS-звонка нельзя автоматически приписывать письмам |
| Защищённые письма | Сохраняются существующие Argon2id/AEAD и двухсекретный формат body, identity-подписи и совместимость старых пакетов | Стойкость парольного слоя зависит от секретов и устройства; этот обзор не доказывает отсутствие всех атак на пользовательский ввод |
| Локальный vault и отдельный архив | Argon2id v19: 64 МиБ, три прохода, p=1; разные контексты `AEGIS-VAULT-v1` и `AEGIS-ARCHIVE-v1`; новые sidecars используют разные AAD | Пароли/ключи могут попадать в память процесса во время использования; гарантированное стирание всех JVM/JCA/native копий не заявляется |
| Глас | Fresh временные сертификаты и TLS 1.3 (EC)DHE, привязка к pinned Ed25519 identity, отдельный Tor onion-маршрут; audio только после ACCEPT/READY | Нет обещания защиты от записи собеседником, захвата микрофона ОС или корреляции Tor. Нативные акустические/сетевые испытания проверяются отдельно |
| Историческая Enigma | Сохранена для совместимости; исходник прямо обозначает режим как непригодный для конфиденциальных данных; legacy UI содержит предупреждение и отдельное подтверждение | Это не современный защищённый шифр. Новые организации/библиотека/голос не используют этот режим. Нельзя рекламировать любой доступный режим как одинаково безопасный |
| Нативная криптобиблиотека | `SodiumBox` загружает комплектный абсолютный путь libsodium | В этом loader нет runtime hash pin, аналогичного `GlasAudioLibraries`; остаётся риск локальной подмены разрешённого исполняемого окружения/упаковки. Подписи обновлений и SHA артефактов не являются универсальной защитой после полного захвата устройства |
| Диагностика Tor/PT | `TechnicalLog` принимает только enum события и число, `TransportDiagnostics` классифицирует строки без записи исходного payload | Время сетевых событий остаётся метаданными. Журналы ОС, Tor и crash dumps не контролируются полностью этим приложением |
| Общая библиотека | Отдельный серверный ACL/SQLite и отдельный зашифрованный клиентский кэш | Общая библиотека не является E2EE личным архивом: полностью скомпрометированный Community server способен прочитать хранимые у него общие материалы. Личные письма, архив и их ключи туда автоматически не отправляются |

## Исправления, сделанные в 5.0.0

- Голосовые правила разделены по направлению и криптографической identity; локальный запрет имеет приоритет. Организационное разрешение берётся только из короткоживущего решения проверенного сервера. Незнакомый/заблокированный контакт не становится доверенным из-за роли.
- Разрешение проверяется до возвращения incoming offer/TLS и при продолжении разговора. Отзыв завершает активный запрещённый звонок, не передавая собеседнику приватную причину отказа.
- Ошибочные ветки Opus, DSP, playback и разбора payload очищают созданные временные буферы в `finally`, сохраняя ограниченные очереди, TTL, replay и consent gates.
- Новый HTTP-ответ связан внутри подписи не только с nonce сервиса, но и с identity запросившего пользователя и SHA-256 точного подписанного запроса. Исправлена возможность подстановки иного корректно подписанного ответа при известном том же nonce.
- Административная повторная аутентификация привязана к identity конкретного сервиса. Клиентские роли/nickname не служат доверенным источником полномочий; служебные worker identity не допускаются к обычным endpoint даже при ошибочной дополнительной роли.
- Решение обработчика и возвращаемый authorization epoch согласованы; операции агента с длительной обработкой выполняются без внешней SQL-блокировки и повторно проверяют контекст.
- HTTP JSON ограничен размером, числом узлов/глубиной/длиной строк/числовой precision и scale; неоднозначные ключи, не-ASCII числовые цифры и чрезмерные экспоненты отклоняются до бизнес-обработчика.
- Исправлен `LocalStore.rekeyCopy`: отдельный кэш `community-v1` до 4 МиБ больше не читается по более низкой квоте mail packet. Реальный большой кэш проверяется после rekey и полного snapshot/restore без смены identity и независимого архива.

## Доказательства и остаточные испытания

- `docs/test-results/5.0.0-glas-migration/`: целевые JSSE TLS/media/state/navigation проверки; тестовые loopback/device seams явно обозначены.
- `docs/test-results/5.0.0-community-http/`: настоящие HTTP/Ed25519/SQLite, проверки request/response binding, replay, malformed input, worker boundary, TOTP/bootstrap и реально запущенный дочерний CLI service.
- `docs/test-results/5.0.0-community-integration/`: production клиент и TorTransport через фиксированный ограниченный SOCKS5 fixture, реальные отдельные vault identities, серверная авторизация, revoke/cache/graph, организационное одобрение и большой cache/rekey/snapshot/restore.

SOCKS fixture не является Tor, а локальное шифрование и JSSE-тесты не являются Windows 11/CachyOS KDE или испытанием двух физических устройств. Итоговый общий прогон, CVE-проверка, официальная цепочка Tor Browser, нативные платформы, network captures, updater E2E и rollback точных релизных бинарников фиксируются отдельно. Старое сообщение владельца о проверке 2.5.0 не является проверкой нового кода 5.0.0. Непроведённые проверки нельзя отмечать PASS.

Никакие закрытые release-signing keys, production Relay/feed и пользовательские identity keys в рамках этого обзора не изменялись. Этот документ не разрешает публикацию Stable; итоговый `productionReady` определяется полными release gates.
