# Взор и Глас 2.5.0 — реальные JavaFX UI-проверки

Финальный локальный прогон: `smoke.log`, результат — `RESULTS.json`. Статус **PASS_HEADLESS** относится к Linux/JavaFX Monocle, а не к нативной приёмке Windows 11 или CachyOS KDE. `productionReady=false`.

Проверены реальные MessengerApp, VzorView и GlasView: 800×600, 100/125/150/200%, темы `minimal-dark` и `classic-light` — 8 сочетаний. Дополнительно фактическими кнопками открыты все 8 разделов и сняты при 1280×850/100%. Всего 48 PNG, перечисленных в JSON. Данные исключительно синтетические: аккаунт blackfox, контакт raven, отдельный зашифрованный временный профиль и отдельный каталог фиктивных файлов для picker. PNG получены `Scene.snapshot`, не сгенерированы.

Проверки компоновки используют реальные размеры сцены, масштаб `localToScene`, границы строк карточек, отсутствие пересечения FlowPane-действий, полный текст заголовков и кнопок. Для «Отмена» и «Выбрать» после прокрутки проверяются пиксельные границы сцены и каждый clipping ancestor, а не только `isVisible()` или программный `fire()`.

Исправленные воспроизводимые дефекты:

- Vzor при 200%: строка режима сессии выходила за карточку (276 логических px). Теперь используется FlowPane с ограничением ширины Selector, у URL и контейнера разрешено сжатие.
- Glas при 200%: минимальная ширина TitledPane выходила за карточку; длинный заголовок и подпись устройства усекались. Минимальная ширина снята, заголовок сокращён до «Проверка соединения», подписи и CheckBox сохраняют высоту переноса, системный выбор обозначен «По умолчанию».
- InWindowDialog/FileChooser: усекались «Назад» и «Открыть папку», заголовок не переносился, текст файлов в тёмной теме был чёрным. Панель адреса перестроена в две строки, используются токены темы. DialogPane внутри VBox корректно прокручивается; прежний `fitToHeight` скрывал кнопки за нижней границей даже после scroll-to-bottom. Исторические неуспешные попытки сохранены отдельно; они не считаются успешными проверками.

Вручную через реальные обработчики проверены русский picker и его отмена, запрет `file://`, фактический отказ запуска по `LINUX_SLIRP_MISSING`, сохранение настроек звука во внутренний зашифрованный sidecar и неизменность messenger session. Окно приложения одно. Вход в Глас и настройки не создают активный звонок, ресурс микрофона или аудиосессию. Кнопки реального вызова/проверки микрофона не нажимались.

Если песочница на целевой машине доступна, только сценарий отсутствующей prerequisites пропускается с `NOT_RUN_PREREQUISITES_AVAILABLE`: smoke не начинает реальную установку/запуск Tor Browser. Нативный toolkit получает статус `PASS_UI_ONLY`; Monocle — `PASS_HEADLESS`. Реальные Tor, HTTPS/onion, браузер, сетевой звонок, микрофон и приёмка целевых ОС — **NOT_RUN** в этом прогоне.

Замер навигации — фактический обработчик кнопки плюс синхронная JavaFX-компоновка (5.57–41.74 ms в финальной сохранённой попытке). Он исключает асинхронную загрузку, ожидание pulses и запись PNG; это не нативный performance gate.

Компиляция: Java 21. Первичный прогон четырёх production UI source и нового smoke выполнен изолированно в `/tmp/aegis-vzor-glas250-visual-vppk07nw`. После дополнительного воспроизведения 24 переносимых строк финальный прогон использовал `/tmp/aegis-shared-dialog250-fix-riv19iic`: только обновлённый InWindowDialog и тестовые smoke-классы впереди общего root `build/local-java21` JAR/classes и зависимостей. Основной build этими проверками не изменялся. Это проверка текущего source, не доказательство финальных установщиков. Root выполняет общий финальный rebuild и повторный запуск кандидата отдельно. SHA-256 фактически прочитанных source и запущенных классов записаны самим smoke в `RESULTS.json`.

CLI smoke: `org.securemail.ui.VzorGlas250Smoke [OUTPUT_DIRECTORY]`. Без аргумента использует `build/vzor-glas250-screenshots`. Требуются JavaFX и зависимости штатного клиента; headless прогон использовал Monocle, native kit не задаёт Monocle автоматически.

Дополнительный общий сценарий: `shared-dialog-horizontal/` содержит 8 реальных снимков и журнал InWindowDialogs200Smoke с 24 Label, переносимыми по фактической ширине. Обнаружен и исправлен отсутствующий HORIZONTAL content bias DialogPane; теперь 150%/200% прокрутка доводит ОК/Отмена до доступной области. Финальные 48 PNG основного smoke повторно сняты после этого fix. Предыдущий проход до content-bias fix сохранён как `pre-content-bias-RESULTS.json` и `pre-content-bias-smoke.log`.
