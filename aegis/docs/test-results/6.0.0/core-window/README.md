# Окно Core 6.0.0 — фактический headless-прогон

Результат: 111 настоящих JavaFX PNG, 0 обнаруженных перекрытий одноуровневых элементов и 0 ошибок буфера Monocle. Проверены размеры 800×600, 1024×768 и 1920×1080, масштаб 100/125/150/200%, светлый и тёмный minimal-пресеты. Для каждой геометрии запускается отдельная JVM, размер окна задаётся до первого показа. Полный визуальный осмотр всех 16 пресетов и нативных окон сюда не входит.

Открыт настоящий `CoreApp600`, выполнен вход через зашифрованный файл ключа устройства и настоящий подписанный Identity HTTP. Организации/новости отрисованы по настоящим Community Gateway/SQLite ответам. Tor readiness, наблюдение блокировки ОС и SOCKS-маршрутизация заменены явно тестовыми backend только в smoke harness. Production test-флагов нет. Проверено отсутствие создания хранилища Почты в профиле Core.

Публичные страницы первоначального назначения владельца, первого делегирования и передачи владельца создаются действующим Core. После блокировки очищаются все поля публичных заданий и подтверждений. Подписание через настоящую Почту этим сценарием не выполняется.

Сценарий отмены согласия использует production `MailPairingBroker600` и отдельную настоящую JVM с явно тестовой точкой входа `MailPairingEntrypoint600`. Fixture компилируется из `client-ui/src/smokeFixtures600` в отдельный проверяемый по SHA-256 JAR; этот каталог не входит в production и обычный smoke source set. Переданы только публичные данные регистрации. Реально работают анонимная stdin pipe, MAC-аутентификация LocalIpc, READY, HEARTBEAT/PONG и SHUTDOWN. Во время ожидания согласия дочерняя JVM удерживает файловую kernel-блокировку. После команды SHUTDOWN она задерживает выход на 1,2 секунды, проверяя независимость FX-потока от ожидания завершения.

`Core.lock()` вернулся за 11/15/14 мс в трёх геометриях. Дочерний процесс получил настоящий SHUTDOWN и завершился, что подтверждено сохранённым `Process.onExit()`, `isAlive=false` и освобождением kernel-блокировки. Pending Future завершился ошибкой, `closingConsents` опустел, поздний callback не восстановил страницу. Затем обычный повторный вход и отдельная гонка настоящего подписанного profile-ответа подтвердили, что очередь JavaFX не восстанавливает приватную страницу после lock.

Воспроизведение: `packaging/tests/run-core-smoke600.py --help`. Нужны JDK 21, CRC-проверенные JAR текущего commit, зависимости, Monocle и проверенные native-библиотеки. Исходники smoke и входные JAR не изменились за весь прогон; точные команды и хеши находятся в EXECUTION.json. Это development snapshot с незакоммиченными изменениями, не финальная привязка релизных бинарников к commit.

Windows 11, CachyOS KDE Wayland/X11, публичный Tor, настоящий GUI Почты, аудио и нативная изоляция здесь **NOT_RUN**. Результат не повышает `productionReady`.
