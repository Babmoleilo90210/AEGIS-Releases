# Библиотека и Obsidian 6.0.0: реализованное и проверенные границы

Код продолжает существующие Java-модули АЕГИС. Личный зашифрованный архив, его ключи и формат не изменены. Production-инфраструктура не развёртывалась; публикация и подпись владельца не выполнялись. Этот компонент сам по себе не устанавливает `productionReady=true`.

## Сервер и доверие

`LibraryServerMain600` действительно выполняет `--init`, `--inspect`, `--serve`. Отдельный loopback-only HTTP сервис использует существующие `ContentService`, `AccessControl`, `CommunityStore` и отдельный Ed25519 service key. Сервер разделяет с Community границу доверия SQLite и производного audit subkey; отдельной изолированной базы/UID для этих данных не заявлено. Приватный Identity/account key не передаётся библиотеке.

`LibraryIdentityBridge600` обращается только к настроенному literal 127.0.0.1 Identity. Он проверяет закреплённую подпись, аудиторию, nonce и точные байты запроса/ответа. Первоначальный authorizeDigest проверяет app proof, связанный с SHA фиксированного domain/action/audience/exact-args envelope. Получатель сам вычисляет SHA. Последующие signed isActive проверки выполняются до и после транзакции, не потребляя nonce повторно. Для привилегированных действий дополнительно используется isStepUpActive. Совместная формальная атомарность двух независимых БД не заявляется; остаётся ограниченное окно между финальной live-проверкой и выдачей сетевого ответа.

AccountPublicKey и nickname зеркалируются только из подписанного Identity ответа после проверки SHA account ID. Owner/Administrator права берутся только из подписанного server-derived контекста и ограничиваются текущим запросом через TrustedContext600. Локальные `global_admins` строки не копируются. Owner не обходит `canRead` закрытых материалов, уровни и членство. Смена identity authority snapshot, device trust или generation прекращает старые разрешения. Identity запрещает Library при sensitive recovery pending до отдельной процедуры двух администраторов.

`LibraryWire600` имеет отдельный домен Ed25519 ответа: аудитория сервиса, outer nonce, длины и SHA точных HTTP bodies. Ограничение 8 MiB не ослабляет Identity framing. Strict JSON отвергает дубликаты и повреждённый UTF8; запросы, очереди и потоки ограничены. Клиент работает через production TorTransport с onion адресом; direct fallback отсутствует. SOCKS fixture в тестах не является Tor-сетью.

## Действительные операции

Каждый read/file/export/projection запрос повторяет текущий ACL. Файл сначала проверяется как вложение LIBRARY, чтобы Library capability не открывала NEWS/EVENT. `read.authorize` требует только READ и возвращает id/revision/SHA тела/политику локальной копии без тела или названия. `project` и `cache.authorize` дополнительно требуют `LIBRARY_EXPORT` и `offlineAllowed`.

Создание, изменение, submit/moderate/publish/retract/delete/revert и link.propose/decide используют существующий ContentService и его отдельные серверные права. `TOPIC` представляет раздел/тему общей библиотеки; утверждённые связи отображаются в графе. `capabilities` и `permissions` возвращают текущие server-derived возможности для интерфейса, но скрытие кнопок не считается проверкой полномочий. Вложения загружаются через ограниченный existing content.files.upload после проверки Library material ACL.

Title-only discovery — отдельная выдача имени конкретному account ID, opaque ID отличается от material ID. По умолчанию закрытые имена, текст и связи не выдаются. Access requests и editor proposals реально сохраняются в новых идемпотентных `library600_*` SQLite таблицах. Решение APPROVED_PENDING_GRANT само по себе не выдаёт READ. Предложение сохраняет baseRevision/changeId/digest, не меняет исходник до утверждения редактором и не перезаписывает более новую версию.

## Клиент, отзыв и кэш

JavaFX `LibraryLauncherView600` соединён с настоящим HTTP клиентом: каталог, граф, просмотр, создание черновика/раздела, Markdown и визуальный редактор, публикация/модерация, связи, предложения и история. Узкое окно переключает панели; используются действующие токены оформления. Provider получает свежую LIBRARY capability и только её app proof private key.

Отображаемое тело имеет отдельный `LibraryReadPermit600`: account/device/generation/ACL epoch, revision и SHA. Серверная перепроверка каждые пять секунд и независимая локальная проверка каждую секунду. Подтверждённый отказ, изменение snapshot/epoch или истечение скрывает тело, очищает управляемые plaintext-проекции и закрывает принадлежащий приложению protected process. Переключение материала также закрывает предыдущую native-проекцию. Online-only RAM snapshot без экспорта требует обновления в пределах 60 секунд. Неопределённость сети не превращается в разрешение: продолжать показ можно только при отдельном явном offline grant и ещё живом монотонном сроке. Длительность измеренного round trip вычитается; локальное signed expiry также ограничивает срок.

`LibraryEncryptedCache600` хранит тело и метаданные отдельно от архива, AES-256-GCM, случайный nonce, аутентифицированные account/device/material bindings. Ключ хранится через существующий OS SystemSecrets (DPAPI/SecretService), без plaintext fallback. Лимит 512 файлов/128 MiB и 1 MiB на текст. После перезапуска дисковый кэш не восстанавливает offline permits: для точного SHA/revision нужен свежий signed per-material cache.authorize. Монотонный permit не сериализуется, wall-clock rollback/expiry отказывает. Нативный DPAPI/SecretService в этом окружении не проверялся; тесты используют явно обозначенную in-memory OS-secret fixture. Core может продолжать online без постоянного кэша при недоступном OS store.

`VaultProjection600` — временные UUID.md в отдельной private-owned папке, atomic publish/fsync, запрет symlink/traversal/активных embeds, ограничения размера. Перезапуск удаляет только собственные старые plaintext-файлы и не восстанавливает lease. Папка не объявляется песочницей. close acknowledgement выдаётся только после фактической очистки/остановки; ошибки завершают future exceptionally. Cleanup работает отдельно от потенциально зависшего worker RPC/open. Локальный expiry timer имеет собственный единственный поток без RPC/native stop; отдельные ограниченные network и cleanup lanes не могут занять его. Реальный stalled read.authorize fixture проверил исчезновение тела и plaintext до возврата RPC после 8-секундного допуска. Обычная смена материала удаляет plaintext и отзывает его RAM lease, сохраняя encrypted disk entries. Подтверждённый deny и явный lock/logout очищают encrypted cache; обычное закрытие освобождает ключ и требует fresh per-material authorization после restart.

## Реальные драйверы Obsidian

Obsidian не включается в АЕГИС и не переименовывается. Координатор загружает официальный пакет через Tor HTTPS, проверяя фиксированный reviewed version/asset SHA/размер и узкий allowlist официальных redirect URL. Это доверие HTTPS + owner-reviewed SHA в дистрибутиве АЕГИС, **не OpenPGP-подпись поставщика**. Текущий reviewed выпуск 1.14.4. После любой замены файла full tree receipt не проходит повторную проверку. Linux tar extractor не исполняет пакет, ограничивает распаковку, отвергает ссылки/traversal/дубликаты и атомарно публикует новую версию. Windows проверенный официальный installer запускается только внутри гостевой Sandbox, не на хосте.

И personal, и protected профили используют ОС-границу. Две папки под одним UID сами по себе не считаются изоляцией.

Linux: bubblewrap + собственный вложенный Xephyr, изолированные mount/PID/user/network пространства; без host home/DBus/audio/clipboard. Protected получает ровно один текущий разрешённый UUID.md, неизменяемый проверенный bundle и только approved plugin settings, без сети. Personal получает только собственные vault/profile RW и свободные плагины внутри границы; slirp4netns отключает host loopback. Личная внешняя сеть — обычная сторонняя сеть, **не обещание Tor-анонимности АЕГИС**. Chromium sandbox не отключается. Guest obsidian.json регистрирует только guest path; схема подтверждена чтением фактического официального app.asar без его выполнения.

Windows: штатная Windows Sandbox, отдельный instance ID, только narrow mappings. Protected отключает сеть/clipboard/mic/video/printers и получает копию одного разрешённого материала. Personal отображает только собственные vault/profile RW и имеет явно отдельную обычную сеть. Lease heartbeat/guest monotonic timeout и host instance close ограничивают жизнь protected copy. Текущая реализация консервативно не запускается при другой активной Windows Sandbox: одновременные Vzor/personal/protected VM остаются ограничением. Создание VM не является доказательством готовности окна Obsidian; реальный installer/renderer lifecycle требует нативной приёмки. Windows Home не получает небезопасного fallback.

Detached personal manager живёт независимо от Core logout, не получает account/root credentials и владеет только собственными процессами. Оба manager JVM удерживают общий `RuntimeLease600` до полного завершения boundary, блокируя замену bundled runtime установщиком. Управление не сканирует/не завершает чужие процессы. Protected coordinator закрывается Core и следит за удалением/заменой исходной проекции.

## Доказательства и незавершённые проверки

Воспроизводимые focused javac/JUnit: 75 PASS, 0 FAIL, 0 SKIPPED на текущем локальном этапе. Здесь реальные Identity HTTP, Library HTTP, SQLite, Ed25519 и production TorTransport поверх loopback SOCKS fixture; unit Authority/OS-secret fixtures обозначены отдельно. SHA исходников проверяются до/после. Последующий общий Gradle прогон выполняется root на замороженном проекте.

JavaFX Monocle smoke использует настоящие HTTP/SQL и сохраняет 6 реальных PNG, в том числе 800×600 при 200%, светлую/тёмную тему. Проверены скрытие закрытого тела, material ACL revoke без смены Identity generation, удаление проекции и независимый cleanup при занятом worker. Форма действительно создала TOPIC черновик, его наличие проверено в SQLite; публикация выполнена через пользовательское меню. Это headless-проверка, не нативная приёмка.

Отдельно фактически скачан официальный Linux архив 1.14.4 (developer curl HTTPS), проверены его точные SHA/размер, production bounded extraction и повторная проверка receipt/tree. Это **не** production Tor download и **не** запуск Obsidian.

NOT_RUN: Windows 11/CachyOS Wayland/X11, настоящий Tor download/сеть, два физических устройства, Windows installer/Obsidian renderer, Linux nested GUI launch, нативный DPAPI/SecretService, Syncthing process и полный межплатформенный updater. Android protected Obsidian остаётся BLOCKED: общая plaintext SAF-папка стороннему приложению не заменяет проверенную песочницу. `SyncthingPolicy600` ограничивает dataset/discovery/relay/NAT/QUIC/proxy fallback, но реальный sync и per-note ACL не заявляются.
