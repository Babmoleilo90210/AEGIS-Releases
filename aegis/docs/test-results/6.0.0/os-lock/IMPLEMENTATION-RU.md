# Наблюдение блокировки ОС — АЕГИС 6.0.0

Реализован `OperatingSystemLockMonitor600.start(Consumer<Reason>)`, возвращающий `AutoCloseable`. Он наблюдает состояние блокировки в отдельном ограниченном фоновом потоке. `LOCKED` и `STATUS_UNAVAILABLE` требуют от вызывающего Core немедленной инвалидизации активной сессии и её выданных разрешений. Наблюдатель не восстанавливает сессию автоматически. `observationAvailable()` предназначен только для диагностики.

Вызов callback выполняется вне JavaFX Application Thread. Core должен направить изменение интерфейса на JavaFX и привязать callback к поколению активной сессии, чтобы отложенный ответ старого наблюдателя не затронул новую сессию. При закрытии Core необходимо закрыть наблюдатель. Повторное уведомление одинаковой причины подавляется; ошибка обработчика повторяется при следующем опросе.

## Windows

Адаптер использует присутствующие в закреплённой зависимости JNA Platform 5.19.1 WTS API: `WTSQuerySessionInformation`, текущую сессию и `WTSSessionInfoEx`. Разметка структуры Windows x64 проверена отдельным тестом: полный размер 232 байта, смещение объединения данных 8 байт и SessionFlags 16 байт. Читаются только уровень, состояние сессии и флаг блокировки; имя пользователя и другие строки не копируются в Java. Память WTS освобождается в `finally`.

Поддерживается только x64 с современной семантикой Windows (major >= 10); документированная инверсия флагов Windows 7 не используется. Неизвестные флаги, ошибочный размер, недоступный API и неподдерживаемая платформа дают STATUS_UNAVAILABLE. Фактическое выполнение WTS на Windows 11 в этой среде: **NOT_RUN**. Проверка разметки и интерпретации полей не заменяет нативную приёмку.

## Linux KDE

Используются фиксированные `/usr/bin/loginctl` и `/usr/bin/busctl`. Проверяются их исполняемость, владелец root и отсутствие права записи группы/остальных на реальном пути и его предках. `loginctl show-session self --property=LockedHint --value` опрашивает logind. `busctl` вызывает KDE `org.freedesktop.ScreenSaver.GetActive` в `/ScreenSaver` на явно проверенной локальной пользовательской шине `/run/user/UID/bus`.

Произвольные DBUS-адреса, TCP, autolaunch и пользовательские команды не принимаются. Каталог runtime должен иметь права 0700 согласно XDG, принадлежать текущему пользователю и не содержать символических ссылок в пути; сокет также должен принадлежать этому пользователю. Переменные окружения дочерних процессов очищаются. Установлены небольшие ограничения времени и вывода. Shell, повышение прав и изменение состояния ОС отсутствуют. Любое достоверное состояние LOCKED блокирует Core; для UNLOCKED требуется согласие logind и KDE. Недоступность любого из них даёт STATUS_UNAVAILABLE. Так учитывается, что LockedHint является подсказкой, обновляемой рабочим окружением.

## Ограничения ресурсов

Планировщик имеет один поток, запросы — один поток и очередь нулевой ёмкости. При зависании нативного вызова новые потоки и задания не накапливаются: наблюдение становится недоступным и Core блокируется. Обычный период опроса — 1 с, общий предел запроса — 3 с. Это опрос с ограниченной задержкой, а не гарантия обнаружения каждой кратковременной блокировки. Дочерние команды останавливаются только через сохранённый объект Process; чужие PID и имена процессов не используются.

## Выполненные проверки

Отдельная компиляция JDK 21 и JUnit после усиления проверки runtime: **18 тестов, 17 PASS, 1 SKIP, 0 FAIL**. Новый тест с настоящим AF_UNIX-сокетом пропущен: текущий системный sandbox запрещает создание такого сокета (`Operation not permitted`). Первоначальная попытка с этой фактической ошибкой сохранена отдельно в `attempt-02-unix-socket-unavailable`; поддельный сокет не создавался. Проверка положительного приёма настоящего пользовательского сокета в этой среде остаётся NOT_RUN. Проверены разметка WTS и современные флаги, строгие парсеры, приоритет LOCKED, fail-closed при UNKNOWN, фиксированные аргументы и очищенное окружение, фактический запуск отдельных JVM-фикстур, ограничение вывода, тайм-аут и завершение только собственного процесса, повтор callback после ошибки и закрытие наблюдения. Точные команды, XML и SHA исходников находятся рядом с этим документом.

Дополнительно вызван настоящий публичный `start()` в текущем контейнере. Получен `STATUS_UNAVAILABLE`, `observationAvailable=false`: рабочая KDE/logind-сессия отсутствует. Это подтверждает обработку недоступной среды, но **не считается** проверкой блокировки Windows/KDE.

Windows 11, CachyOS KDE Wayland и CachyOS KDE X11, реальные события блокировки/разблокировки и приостановки компьютера: **NOT_RUN**. Тесты адаптера не заменяют эти испытания.
