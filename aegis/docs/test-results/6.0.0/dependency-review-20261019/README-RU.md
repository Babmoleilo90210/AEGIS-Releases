# Повторная проверка зависимостей: 19 октября 2026 г.

Реально выполнена одна ограниченная серия запросов к официальному OSV API и восьми первичным страницам безопасности/выпусков. Приватные данные, исходный пользовательский текст, ключи и файлы переписки не отправлялись. Эта проверка **не устанавливает productionReady=true** и не заменяет итоговый SCA упакованных файлов, аудит клиента или нативные испытания.

Проверены SHA-256 **52 восстановленных JAR**: 51 файл соответствует Gradle verification metadata, ещё один — отдельно закреплённый JUnit console test tool. Это 47 разных Maven coordinate/version; 38 JAR/33 coordinate совпадают с объявленными runtime pins. Остальные включают test tools и прежние verification inputs. Это не утверждение, что все 52 JAR должны входить в продукт: окончательное разрешение Gradle conflicts и фактический package inventory определяют конечную runtime closure. Дополнительно проверены шесть Android JAR/AAR по текущим `DEPENDENCIES.json` pins.

Отправлен batch из **71 продуктового/входного запроса**: 53 Maven coordinate/version, восемь native versions и десять точных source commits. Все 71 результата не содержат индексированных advisory IDs и не требуют следующей страницы. Точная формулировка результата: `NO_INDEXED_HITS_FOR_SUBMITTED_IDENTIFIERS`. Пустой результат не доказывает распознавания всех пакетов/forks, отсутствия уязвимостей, безопасных build flags или полноты индекса.

Отдельный 72-й запрос — **положительный контроль API**, заведомо устаревший `log4j-core:2.14.1`, не зависимость АЕГИС. Он вернул семь GHSA IDs, что подтверждает фактическую работу механизма обнаружения известных проблем, а не принятие пустого/ошибочного ответа за успех. Raw OSV request/response и SHA сохранены. API-контроль не является показателем безопасности продукта.

По первичным источникам семь HTTP 200: официальные OpenSSL vulnerabilities/release notes, PDFBox security, Commons Compress security, SQLite security и публичные advisory API libsodium/Gson. Запрошенная страница Opus security вернула **HTTP 404 — BLOCKED**, без повторения неработающих запросов. В `PRIMARY-OBSERVATIONS.json` сохранены собственные ограниченные выводы; в основном отчёте — URL/даты/status/размер/SHA точных ответов. Полные сторонние HTML-страницы не перепубликуются в исходном пакете.

OpenSSL inventory остаётся **3.5.9** по прежнему source/native/AAR match, а не ошибочные 3.5.7 из upstream README. Свежие официальные release notes описывают 3.5.9 как security patch; это не отменяет проверку конкретных build flags/экспозиции. PDFBox security различает `ExtractEmbeddedFiles` example и core library; текущая 3.0.8 находится за указанной там границей исправления CVE-2026-33929. Аналогично версия Commons Compress 1.28.0 находится за конкретными старыми fixed-version границами, рассмотренными на текущей странице; новые или неиндексированные дефекты этим не исключаются.

Для нового отдельно закреплённого Android libsodium stable snapshot **`c44f62b9919e4cce5963e74c67a43b8818ed523bd2eded506266d8797d103baf`** независимо повторно проверены обе официальные minisign-подписи: payload и trusted comment. Изменение mutable download URL не принято автоматически. Ключ сверяется с закреплённым официальным public key; owner private key не нужен. Это подтверждение происхождения source archive, а не отсутствие уязвимостей или выполнение JNI на Android.

Сравнение входных metadata hashes до/после всей серии: `inputSourceUnchanged=true`. Те же hashes ещё раз совпали при переносе отчётов в репозиторий. `SBOM-REVIEWED-INPUTS-6.0.0.cdx.json` описывает рассмотренные Maven/native **входы**, отдельно помечая source-archive/AAR pins. Его нельзя выдавать за полную ведомость окончательных EXE/AppImage/APK/ELF. Финальная упаковка должна сверить фактически включённые файлы и notices.

Воспроизведение выполняет `tools/audit-dependencies600.py`: указать `--project`, каталог `--maven-dir`, `--android-sdk`, точные `--sodium-source`/`--sodium-signature` и отдельный `--out`. Используются TLS verification, запрет redirects, ограничение ответа, timeout и максимум три параллельных primary fetch. Нет бесконечных retry. Основной JSON хранит все параметры запросов и hashes. Возврат скрипта 0 означает завершение ограниченного OSV/input review с работающим положительным контролем; частичная primary coverage всё равно отражена явно и не делает Security gate успешным.
