# Проверка реального публичного источника новостей

18 октября 2026 года выполнены две попытки запустить существующий `NewsWorker` с публичным официальным RSS Debian. Адрес `https://www.debian.org/News/news` получен из RSS-ссылки официальной страницы `https://www.debian.org/News/`. Последняя доступна через поиск и ссылается на feed с `application/rss+xml`; это не доказательство сетевого доступа самого Java-процесса.

**Сбор источника BLOCKED:** системный DNS в этой среде возвращает `UnknownHostException` для `www.debian.org` до HTTPS/robots. После второй попытки внешние повторы остановлены. Не отключались проверка DNS/public IP, HTTPS, robots, ограничения ответа или SSRF-защита. Содержимое feed, статьи, изображения и полные тексты не загружены и не включены в доказательства. `RESULT.json` содержит точную причину; выход процесса 0 означает завершённое измерение, а не успешный сбор.

Локальная часть выполнялась через настоящие `AgentService`, `NewsWorker`, `CommunityStore`/SQLite, `ContentService`, `AccessControl`, а не подставленные результаты. В новой частной тестовой DB создана отдельная служебная identity только с `AGENT_WORK`, отдельный издатель только с `NEWS_CREATE`, один явно заданный негеографический тестовый регион и один разрешённый источник. Заполнение тестовой DB выполнено SQL fixture; административная процедура с двумя администраторами и серверная аутентификация этим прогоном не проверялись. Уведомления никому не отправлялись. Production не использовался.

Фактически проверено:

- Выключенный агент не создаёт задание и не делает запросов.
- Два последовательных запуска настоящего scheduler создают одно задание в SQLite.
- Worker не получает доступ к личной библиотеке.
- После отказа источник сохраняет `SOURCE_UNAVAILABLE`; немедленный повтор соблюдает backoff и не делает второго сетевого запроса.
- В DB нет кандидатов, материалов и уведомлений; модельные или платные запросы не выполнялись.

Проверки нормализации дат/происхождения наблюдений, дедупликации публикаций, смысла новостей, независимости источников, настоящего ИИ-пересказа и автоматической публикации остаются **BLOCKED**. Дедупликация заданий не подменяет дедупликацию публикаций. Локальная модель не установлена, внешние API и секреты не использовались. Проверка Tor, региональной точности, нативных ОС и production остаётся за пределами этого прогона. `productionReady=false`.

`NewsPublicSourceSmoke600.java` — только opt-in тестовая утилита. Инструментация записывает метаданные сетевых операций и делегирует обмен неизменённому production `PublicSourceHttp`, который сам проверяет DNS и закрепляет публичный IP для TLS; подставленных feed-ответов и модельных результатов нет. При доступном источнике вызывается реальный `HttpNewsModel` с явно недоступной локальной моделью, чтобы проверить закрытый отказ без фиктивной публикации. В этом прогоне до модели выполнение не дошло.

Воспроизведение с актуальными закреплёнными JAR и новым выходным каталогом:

```sh
python3 docs/test-results/6.0.0/server/news-public/run.py \
  --jdk /absolute/path/to/jdk-21 \
  --dependencies /absolute/path/to/pinned-runtime-jars \
  --output /absolute/path/to/new-output
```

`RUN.json` сохраняет SHA-256 действительно скомпилированных исходников и зависимостей, команду, окружение и `sourceUnchanged=true` для второго диагностического прогона. `compile.log`, `run.log`, `RESULT.json` относятся к этой попытке. Тестовая DB и временные синтетические ключи не входят в публичные доказательства.
