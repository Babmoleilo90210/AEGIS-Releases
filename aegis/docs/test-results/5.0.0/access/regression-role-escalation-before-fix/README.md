# Воспроизведение повышения полномочий до исправления

Эти ожидаемо неуспешные JUnit результаты сохранены как доказательство обнаруженного дефекта. Они не являются результатом окончательной версии. Использованы реальные временные SQLite БД, Ed25519 и TOTP; production данные отсутствуют.

Проверки self-role и assigned-descendant ancestor ожидали отказ при добавлении невыданных полномочий. Обе завершились FAIL, потому что сервер разрешал действие. До исправления AdminService сначала изменял граф ролей, а затем вычислял права самого инициатора из уже изменённого графа. SHA-256 AdminService до исправления: `b8fc07040a7badbd56a5ca392a45e675fd239fe4d11fc93a1c103b9913dcb59b`.

В окончательном исходнике authority (набор разрешений, уровень, статус администратора) фиксируется до мутации в той же транзакции. Общий повторный прогон включает оба отрицательных сценария, отдельный clearance-only сценарий и разрешённое переименование собственной роли. Окончательные результаты находятся на уровень выше.
