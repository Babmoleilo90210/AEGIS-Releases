## Существенные решения и их приоритет

Прослежены требования 1.1.0 к единому окну, локальному offline vault, неизменным identity, Tor/Snowflake/Relay и проверке подписи до разбора updater manifest; 1.1.5 — Appearance Engine, 16 пресетов четырёх категорий, пользовательские макеты, системные сообщения обновлений; 1.2.0 — стабильность Tor, различие Relay acceptance/device delivery/read receipts и корректная семантика исчезающих писем; 1.5.0 — отдельный пароль и необязательный recovery key архива, зашифрованный индекс, папки/теги/корзина, резервные копии, список/таблица/карточки и P2P-проверка. Это история требований и сообщений, не повторное исполнение старых тестов.

Последний пользовательский UI-комментарий planning chat, сообщение `bace0c3a-e970-4fc7-b83b-4ba1812324cf`, подтверждает: шапка уже одобрена; контакты и письма служат удачными образцами; кнопки нужно выровнять и сделать компактнее; поиск упростить; публичные профили и аватары проверить между пользователями; категории настроек объединить на скруглённой подложке; содержимое открывать **внизу**, а не справа. Более раннее решение убирает отдельный Friends и сохраняет переставляемую основную навигацию.

Сообщение `d53cfe34-347a-4dc8-a142-20b4a4d9f2b0` меняет историческую roadmap местами: Safe Web — 2.0.0, Secure Voice — 2.5.0. Позднейшее подробное ТЗ 2.0.0 объединяет Safe Web с Interface Refinement. **Для текущей разработки приоритет имеет последний ТЗ 2.5.0 из рабочего разговора:** названия «Взор»/«Глас», голос через Tor, минималистичные SVG-значки, сохранение 16 пресетов, исправление галереи и строгие внешние release gates. Отдельной raw-копии этого последнего prompt среди двух HTML нет; исторические назначения версий не подменяют актуальное задание. Старые разрешения на публикацию конкретных 1.x не дают разрешения публиковать нынешний Stable.

## Ограничение provenance исходников и сборок

Фактическая база текущей ветки — `f173b4a1bb5f1e3ed121870aa04a6583833f93e9`, опубликованная development-база 2.0.0 Beta, продолжающая 1.5.0; `git describe` показывает `v1.5.0-2-gf173b4a`. Поэтому текущую работу нельзя описывать как новую ветку непосредственно от неизменённого tag 1.5.0 либо от устаревших 1.2.0 исходников.

В [`base-source-verification.json`](base-source-verification.json) зафиксировано совпадение 604 файлов опубликованного source ZIP с Git, SHA-256 source ZIP `ade6108509ac837d9781ff3f03ebfe0bd9c917b332bbf221de0ed9ca28c90633` и опубликованного AppImage `4e75b00b93b3ed6321f40b5e6052cb954d5ceafaad1ed7ad802c3eb57fb6e687`. Этот документ сверяет существующую запись проверки; не выдаёт её за повторно выполненную независимую воспроизводимую сборку. Подписанная CI provenance старого релиза не предоставлена. Слова прежнего assistant «всё проверено» и старые пользовательские PASS не доказывают прохождение нативной приёмки текущих бинарников 2.5.0. Привязка новых артефактов к замороженным исходникам, SHA-256 и актуальные тесты фиксируются отдельными release-отчётами; обязательные непроведённые испытания сохраняют `NOT_RUN` и `productionReady=false`.
