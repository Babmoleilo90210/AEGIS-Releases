# Аутентификация дистрибутива Tor Browser

`TorBrowserSignature` проверяет отдельную OpenPGP-подпись официального архива/установщика до распаковки или запуска. Проверка выполняется на Java через Bouncy Castle 1.86, без GnuPG, shell и глобального JCA provider. Это отдельная цепочка доверия, не связанная с identity keys или Ed25519 release-signing key АЕГИС.

## Источник доверия

Закреплён полный fingerprint первичного ключа Tor Browser Developers:

`EF6E286DDA85EA2A4BA7DE684E2C6E8793298290`

Официальное описание: <https://support.torproject.org/tor-browser/getting-started/verifying-tor-browser/>. Оно указывает этот fingerprint и разрешает получить публичный ключ из <https://keys.openpgp.org/vks/v1/by-fingerprint/EF6E286DDA85EA2A4BA7DE684E2C6E8793298290>.

Публичный ключ получен 15 октября 2026 года и включён в ресурсы `client-core`. Fingerprint проверен при подготовке и повторно вычисляется из пакета публичного ключа при каждой проверке. Сведения об источнике и SHA-256 снимка находятся рядом с ключом в `tor-browser-developers-provenance.json`. Сторонние сертификации не создают доверия.

Публичный метод с `InputStream publicKey` позволяет проверить обновлённый keyring с новыми подключами и отзывами, сохраняя тот же закреплённый fingerprint. Пользователь не может передать другой production trust anchor через публичный API, настройки или environment. Проверки с другими ключами доступны только через package-private метод для unit fixtures.

## Что проверяется

- Один публичный keyring; один binary detached signature; отсутствие зашифрованных, сжатых, secret-key, partial-length и неопределённых OpenPGP-пакетов.
- Fingerprint первичного ключа, его математическая self certification, срок действия и собственные подписанные отзывы.
- RSA v4 не менее 3072 бит; SHA-256, SHA-384 или SHA-512. Иные алгоритмы отклоняются до изменения политики после отдельной проверки совместимости.
- Подключ подписанта должен быть математически связан с закреплённым primary key. Требуется флаг SIGN_DATA и back signature подключа, связывающая оба ключа.
- Creation time подписи, signature expiry и key expiry; будущие подписи отклоняются. Истёкшие сейчас ключи отклоняются даже для старых архивов.
- Отзывы используемого подписывающего подключа, issuer fingerprint, неизвестные critical subpackets и неоднозначные дубликаты важных hashed subpackets.
- Подпись точных байтов архива и одновременно SHA-256. Архив читается потоково, максимум 1 GiB; metadata максимум 1 MiB; один packet максимум 64 KiB и максимум 512 пакетов.
- Финальные symlinks, пустые файлы, изменение размера, file identity или mtime во время проверки отклоняются.

Установщик должен копировать исходники в закрытый staging directory и сравнивать полученный SHA-256 перед использованием. Один лишь успех проверки подписи не доказывает актуальность версии, работоспособность браузера, сетевую изоляцию или защиту профиля.

## Ограничение отзывов

Офлайн-снимок ключа не может сообщить об отзыве, выпущенном после его получения или скрытом источником. Для обновления снимка допускается официальный keyring с тем же primary fingerprint; новый primary fingerprint требует отдельного изменения доверенной политики. Сбой получения ключа или криптографической проверки не даёт права запускать неподтверждённый файл. Отсутствие доступа к официальному архиву не отмечается как успешная проверка реального дистрибутива.

## Выполненные испытания

17 unit tests с настоящими криптографическими операциями на одноразовых RSA3072 ключах: валидные подписи primary/subkey, back signature, изменение архива, неправильный primary pin, отсутствие binding/back signature, отзыв primary/subkey, истечение ключа, будущая подпись, SHA-1, отсутствие SIGN_DATA, несколько signatures, некорректные/слишком большие metadata, oversized архив, symlink, ASCII armor. Все 17 прошли в доступной Linux Java 21 среде.

Продукционный API дополнительно загружает реальный включённый публичный ключ Tor и проверяет его текущую self certification; fixture signature затем ожидаемо отклоняется как подпись неизвестного подписанта. Это не реальный официальный Tor Browser archive end-to-end: для такого утверждения требуются байты официального дистрибутива и соответствующая `.asc`.
