# Новости и мероприятия АЕГИС 5.0.0

## Система и границы

Раздел «Новости» работает через отдельный community-server. Production Relay переписки не превращён в новостной сервер. Клиент обращается к настроенному доверенному onion-сервису через существующий Tor transport; запросы подписаны существующей Ed25519 identity пользователя, ответы — закреплённым ключом общего сервера. Сервис не получает личные письма, ключи архива, recovery key или пароль аккаунта.

Новости, события, библиотечные материалы и файлы хранятся на сервере в SQLite. Личный зашифрованный архив остаётся отдельным локальным хранилищем. Базовые письма и звонки не требуют платной модели ИИ или доступности общего сервера.

## Ленты

Предусмотрены всеобщая, городская и организационная выборки. `distribution` принимает GLOBAL, CITY, ORGANIZATION; это географическая/редакционная область публикации, а не уровень допуска. Внутренняя `policy` определяет, имеет ли конкретный пользователь право чтения.

Город задаётся явно нормализованным идентификатором `страна/регион/город`, например `ru/ru-mow/moscow`. Одноимённые города разных стран не смешиваются. Город не вычисляется по IP. Для публикации организации сервер берёт город из утверждённой записи организации. Отсутствие города не запрещает организационные новости, но препятствует выдаче материала за городской.

Для всех лент сервер сначала проверяет текущие права, затем выдаёт разрешённые объекты. Не возвращается общее число закрытых материалов. Поисковая строка, дата, тип, организация и пагинация применяются на сервере. Один ответ содержит не более 100 материалов.

## Публикация

Состояния: черновик, подано на проверку, одобрено, опубликовано, исправлено, отклонено, отозвано. Создание, редактирование, модерация, публикация, удаление, экспорт и изменение политики — разные полномочия. Высокий допуск не заменяет эти разрешения.

Автор с правом CREATE создаёт черновик и подаёт его на проверку. MODERATE позволяет принять или отклонить заявку. PUBLISH позволяет публиковать одобренные материалы; специально уполномоченный издатель может создать и опубликовать собственный редакционный черновик. Для всеобщей новости дополнительно требуется глобальное `NEWS_GLOBAL_PUBLISH`. Организация не может делегировать это глобальное разрешение себе самостоятельно.

Клиент не назначает автора, AI-флаг, состояние публикации или административные признаки. Неизвестные поля отвергаются. При каждом изменении требуется актуальный `revision`; конкурентная запись со старой версией получает CONFLICT. Восстановление прежнего текста создаёт новую редакцию. Политика допуска при восстановлении не откатывается.

Повторная публикация исправленного текста получает состояние CORRECTED. Читателю доступны текущая версия и история номеров/дат редакций. Старое содержимое редакций доступно только текущему читателю с отдельным EDIT; оно не раскрывается через публичную историю.

## Редактор, вложения и взаимодействие

Канонический формат текста — Markdown. JavaFX-компонент DocumentEditor предоставляет исходный и визуальный режим редактирования блоков. Переключение режимов не преобразует и не уничтожает исходник. HTML/JavaScript не исполняются. Изображения и внешние ссылки не загружаются автоматически через обычный сетевой стек.

Файлы прикрепляются к сохранённому черновику. Изменить вложения опубликованного материала без возвращения к черновику нельзя: это предотвращает обход права публикации. Лимит файла — 4 МиБ, материала — 32 вложения / 32 МиБ. Разрешены проверенные по сигнатуре PNG/JPEG/WebP, PDF, MP4 и UTF-8 plain/Markdown. Исполняемые форматы, SVG и HTML не принимаются. Скачивание требует текущего доступа к родительскому материалу и выполняется только по явному выбору пользователя. Файлы не запускаются автоматически.

Поддержаны четыре реакции и их суммарные количества. Комментариев нет. Опрос содержит 2–12 вариантов; сервер проверяет принадлежность варианта конкретному материалу. Один пользователь имеет один голос с возможностью изменить выбор. Закрытая публикация не становится доступной через API опроса или реакции.

## Мероприятия

Событие хранит название, описание, epoch-время начала, место/онлайн-формат, организатора и вместимость. Нулевой лимит мест означает отсутствие фиксированной вместимости. Регистрация и проверка остатка мест выполняются одной транзакцией; повторная регистрация идемпотентна. Не допускается регистрация на завершившееся или неопубликованное событие.

Перенос сохраняет участников, создаёт новую редакцию и уведомление. Отмена отзывает событие и уведомляет записанных участников. Участник видит отменённый статус только при сохранении текущего доступа. Другие пользователи не получают имена участников из общего ответа.

## Уведомления и ИИ

Внутренний центр уведомлений объединяет модерацию, мероприятия и сообщения организаций/ролей/подтверждений. Перед показом названия связанного материала сервер повторно проверяет доступ. Категории можно отключать; записи ограничены по количеству. Уведомления не являются способом обойти ACL.

Автономный новостной агент описан в AI-NEWS-AGENT-5.0.0.md. В content sink AI-происхождение устанавливается только внутренним центральным обработчиком. Рабочий узел не получает API публикации. Сомнительные, важные и не подтверждённые центральной проверкой материалы должны попадать редактору; модельная уверенность сама по себе не доказывает достоверность.

## Проверки и ограничения

`ContentServiceTest` выполняет настоящие транзакции SQLite и production AccessControl: IDOR, скрытые черновики, отзыв доступа, глобальное разрешение, модерация, города, конкурентные редакции, опросы, вместимость, отмена/уведомления, файлы, источник AI-флага и сохранение после перезапуска. Это локальные автоматические проверки, а не Tor E2E или нативная приёмка.

Текущий поиск рассматривает до 5001 кандидата за запрос; для крупных установок необходимо развивать ACL-индексы, сохраняя отсутствие скрытых счётчиков. Подпись ответа доказывает происхождение от доверенного сервера, но не истинность новостного сообщения. Общий сервер видит доступные ему публикации и метаданные запросов; новости не заявляются как E2EE-переписка.
