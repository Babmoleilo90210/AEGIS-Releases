# Взор — АЕГИС 2.5.0

Взор продолжает Safe Web версии 2.0: внутри JavaFX находится компактная панель управления, а страницы открываются в официальном Tor Browser отдельным окном. Собственный браузерный движок, JavaFX WebView, браузерные расширения АЕГИС и привилегированное управление вкладками не добавлены. Tor Browser запускает собственный Tor, независимый от почтового Tor АЕГИС.

Статус этой реализации: автоматические и fixture integration проверки выполнены; обязательная нативная и сетевая приёмка официального браузера ещё **NOT_RUN**. `productionReady=false`.

## Открытие

Откройте раздел «Взор», проверьте адрес и нажмите «Открыть Взор». Основной сценарий не требует ручного поиска executable-файла, архива или подписи:

1. АЕГИС проверяет доступность поддерживаемого механизма изоляции, не меняя компоненты ОС.
2. Проверяет целостность ранее удостоверенного browser template и сохранённой обычной сессии.
3. При первой подготовке или необходимости повторного удостоверения подключает почтовый Tor, получает официальные сведения о стабильной версии, пакет и `.asc` через его отдельный HTTPS SOCKS-контекст.
4. Проверяет OpenPGP-подпись, внутреннюю версию Tor Browser и x86_64 архитектуру, устанавливает отдельный bundle и открывает выбранную сессию в sandbox.

Ожидание Tor, загрузка, проверка, распаковка и запуск выполняются вне JavaFX Application Thread. Панель показывает состояние операции и прогресс; «Отменить» прекращает подготовку. При отсутствии сети нет прямого HTTPS fallback. После устранения причины можно повторно нажать «Открыть Взор». Поздняя отмена уже завершённую установку не удаляет, но запрещает оставлять запущенный браузер от отменённой операции.

Панель «Дополнительные настройки» содержит резервный импорт официального пакета с соответствующей `.asc` и поиск уже имеющихся установок. Обнаружение только сообщает о найденном Tor Browser: чужой профиль, пароли, cookies, история и закладки не читаются и не переносятся. Для Взора используется отдельная удостоверенная копия. Изменённые локальные файлы не объявляются подлинными повторным вычислением собственных хэшей.

## Адреса и письма

Разрешены полные HTTPS-адреса и HTTP-адреса onion v3. `file:`, `javascript:`, `data:`, команды, credentials в authority URL, локальные имена, числовые IP, управляющие символы и browser switches отклоняются до запуска. URL передаётся одним проверенным аргументом либо ограниченными данными гостевого запуска; shell-код из адреса не составляется.

В открытом письме выделите URL и выберите «Ссылка → Взор». Взор показывает выбранный адрес; открытие требует отдельного нажатия пользователя. Передаётся только URL. Всё письмо, вложения, ключи, пароли и данные аккаунта в браузер не отправляются. Для защищённого письма действие доступно после разрешённого раскрытия содержимого.

Если браузер уже работает, начало новой сессии требует подтверждения закрытия текущих вкладок. «Новая сессия» перезапускает выбранный режим. Штатные «Новая личность», «Новая цепочка для сайта» и уровни Standard/Safer/Safest остаются в меню Tor Browser; АЕГИС не подменяет их удалёнными командами. Индикатор Tor почты не является доказательством подключения Tor браузера: окончательный статус подключения и уровень защиты смотрите в самом Tor Browser.

## Сессии и обновления

Обычная сессия сохраняет разрешённые штатным Tor Browser данные, включая закладки и настройки, в отдельной копии bundle. Это не обещание сохранения cookies или истории: их срок жизни определяется штатной моделью Tor Browser. Временная сессия использует другой bundle и удаляется только после подтверждённой остановки собственных процессов/VM. Обычное удаление файлов не является гарантированным физическим стиранием SSD, snapshots или резервных копий файловой системы.

Контрольные manifest, receipt, версии и исходные проверенные template находятся вне доступного браузеру дерева. Каждый последующий запуск сверяет executable-файлы с удостоверенным template. При изменении файлов, включая штатное MAR-обновление, нужен свежий подписанный официальный пакет. Updater Tor Browser не заменён собственным updater АЕГИС.

Повторная удостоверенная установка той же версии может восстановить повреждённые executable-файлы. Новая копия готовится отдельно, сохраняет собственные Browser Data и загрузки, проверяется и публикуется с rollback при ошибке. При сбое между перемещением старого bundle и публикацией нового manager восстанавливает резервный каталог до очистки незавершённого staging. Служебные Mozilla `lock`, `.parentlock`, `parent.lock` непосредственно в `profile.default` не переносятся после подтверждённой остановки; они не являются закладками или пользовательскими настройками. Остальные небезопасные ссылки останавливают перенос, сохраняя исходные данные.

## Загрузки и архив

Откройте сворачиваемую панель «Загрузки» и обновите список. Отдельный каталог `aegis-downloads` находится внутри соответствующей браузерной сессии и не является зашифрованным архивом АЕГИС. В Linux он доступен браузеру как `/home/web/Downloads`; Windows bootstrap устанавливает штатный download directory в каталог сессии.

АЕГИС не запускает скачанные executable-файлы и не импортирует файлы автоматически. Для импорта выберите файл и нажмите «Импортировать в архив». После явной разблокировки архива АЕГИС создаёт ограниченный приватный снимок выбранного файла вне browser mount, проверяя подмену пути, ссылок и файла во время чтения. Только снимок передаётся существующему механизму шифрования архива. Ключ архива в браузер не передаётся. Импорт не делает произвольный файл безопасным для последующего исполнения.

## Поддерживаемые механизмы ОС

| Среда | Условия реализации | Нативная приёмка 2.5.0 |
| --- | --- | --- |
| CachyOS KDE X11 x86_64 | Системные bubblewrap, slirp4netns, Xephyr, user namespaces, локальный DISPLAY | NOT_RUN |
| CachyOS KDE Wayland x86_64 | Те же компоненты и работающий Xwayland для вложенного Xephyr | NOT_RUN |
| Windows 11 24H2+ x64 Pro/Enterprise/Education | Виртуализация, Microsoft Windows Sandbox и актуальный официальный CLI `wsb` | NOT_RUN |
| Windows Home | Microsoft Windows Sandbox не поддерживается; изолированный запуск Взора этим backend недоступен | UNSUPPORTED |
| Windows до 24H2 или без нужного CLI | Текущий управляемый backend недоступен | UNSUPPORTED |

Отсутствующий или небезопасный компонент показывает понятную причину до большой загрузки браузера. Наличие prerequisites ещё не доказывает успешный запуск. АЕГИС не устанавливает компоненты ОС и не переключается на обычный не изолированный браузер.

Linux использует отдельные filesystem/process/network namespaces, ограниченные системные read-only mounts, slirp без host loopback и вложенный Xephyr. Host home, D-Bus, аудиоканалы, обычный X socket и clipboard браузеру не предоставляются. Windows использует собственную VM Microsoft Windows Sandbox с единственным writable mapping browser bundle; clipboard, input devices, принтеры и vGPU отключены. Host-private ID и CLI управляют только собственной VM. При неподтверждённой остановке контроллер, receipt, профиль и блокировка сохраняются для повторного закрытия.

## Подлинность и результаты

Стабильные официальные discovery endpoints дают имена пакетов для нужной платформы. JSON не заменяет подпись. До распаковки Linux TAR или исполнения Windows portable EXE фиксируется snapshot точных байтов и проверяется OpenPGP primary fingerprint Tor Browser Developers `EF6E286DDA85EA2A4BA7DE684E2C6E8793298290`. Для пользователя Python/GnuPG не требуются. Внутренняя версия берётся из подписанного `Browser/tbb_version.json`; `application.ini Version` относится к Firefox и не используется как версия Tor Browser. Реальные ELF/PE headers Firefox и Tor должны соответствовать x86_64.

Монотонная отметка версии не даёт обычным импортом откатиться ниже ранее удостоверенного пакета. Она не доказывает свежесть самого первого пакета или успешность неизвестного АЕГИС MAR-обновления. Embedded keyring не знает будущих изменений/отзывов ключей; неизвестная подпись отклоняется, и keyring должен поступить через обычное удостоверенное обновление приложения.

На 15 октября 2026 web retrieval официальных per-platform JSON показывает Tor Browser 15.0.25. Нативные запросы из среды разработки получили HTML SiteUnavailable вместо JSON. Это не успешная загрузка: реальный официальный пакет, его подпись, native browser launch, HTTPS/onion, DNS/WebRTC и отсутствие прямого браузерного трафика в данной среде **NOT_RUN**.

69/69 выбранных unit и fixture integration тестов прошли: настоящий disposable OpenPGP, XZ/TAR и production HTTP parser; настоящий loopback SOCKS handshake и отмена сокета; URL/version/source policy, повреждение файлов, отмена, восстановление, antirollback и сохранение Browser Data. Эти проверки не подменяют нативную приёмку. Отчёты: `docs/test-results/2.5.0-tor-browser/`. Полная архитектура получения пакета описана в `TOR-BROWSER-ACQUISITION-2.5.0.md`; границы гарантий — в `VZOR-THREAT-MODEL-2.5.0.md`.
