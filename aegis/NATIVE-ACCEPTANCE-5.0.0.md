# Нативная приёмка АЕГИС 5.0.0

## Фактический статус

На момент подготовки исходников доступен Linux-контейнер без целевых desktop-сред, двух физических устройств и инфраструктуры владельца. Windows 11 x64, CachyOS KDE Wayland и CachyOS KDE X11 для **точной сборки 5.0.0**: NOT_RUN. Локальные JavaFX/SQLite/JUnit/HTTP-фикстуры документируются отдельно и не заменяют эти результаты. Предыдущее подтверждение владельцем версии 2.5.0 не переносится автоматически на изменённые бинарники 5.0.0.

`productionReady=false`. Ни упаковка, ни успешный exit code скрипта, ни правильный manifest не дают оснований изменить это значение. Финальная приёмка привязывается к sourceCommit/sourceTree и SHA-256 всех артефактов после заморозки.

## Отдельные безопасные стенды

Используйте резервные тестовые копии профилей. Сохраните контрольные суммы identity, писем, вложений и архива до испытания, не публикуя приватные байты. Не проверяйте разрушительный rollback на единственном личном архиве.

Для организаций/новостей/библиотеки требуется настроенный отдельный community-server и два администратора с разными проверенными Ed25519 identity и TOTP. Рабочий ИИ-узел имеет отдельную минимальную service identity. Production Relay не изменяется. Новые серверные компоненты размещаются только в отдельно разрешённой тестовой инфраструктуре.

Windows: фиксируйте реальную редакцию/сборку. Взор с текущим Windows Sandbox backend требует поддерживаемой редакции и возможностей штатного Sandbox; Windows Home не получает PASS посредством запуска браузера без изоляции. Глас и остальные функции проверяются отдельно. Повышаются только разрешённые точечные операции UAC, а не всё приложение.

CachyOS: повторите испытания в KDE Wayland и KDE X11 отдельно. Запишите XDG_SESSION_TYPE, compositor/Xwayland и установленные разрешённые bwrap/slirp4netns/Xephyr. Наличие пакетов не доказывает запуск браузера. При ошибке песочницы запрещён менее защищённый fallback.

Сохраните настоящие снимки. Проверяйте галерею, полные подписи архивных меню, три блока, шесть категорий ниже панели и отсутствие лишних Stage.

## Два физических устройства

Нужны две разные физические машины в независимых внешних сетях. В отчёте достаточно обезличенных меток, без реальных IP. CROSS-01..15 соответствуют: письма; профили; аватары; Глас; identity; Tor-only; роли; отзыв; новости; городская лента; библиотека; скрытые материалы; encrypted cache; потеря сети; безопасное восстановление.

Звонок проверяйте реальной речью в обе стороны, включая не менее 60 минут для сохранения длительной приёмки Гласа, нагрузку и совместную работу браузера/переписки/архива. До принятия и криптографической аутентификации микрофон должен быть закрыт; после завершения — освобождён. Пакетный захват и firewall-наблюдения сохраняйте как секретно сокращённую сводку. Успех loopback SOCKS fixture не подтверждает скрытие IP или отсутствие DNS-утечек.

Проводите сравнение на отдельных резервных копиях. Защищённая backup должна появиться до структурных изменений. Сбой не должен удалять старую копию. Новые разделы добавляются внутри блока, сохраняя пользовательский порядок прежних элементов.

## Signed updater E2E

Положительный сценарий требует **реального manifest, подписанного владельцем закреплённым Ed25519 ключом**. Приватный ключ остаётся офлайн; kit не запрашивает его. Используйте отдельный тестовый канал/адрес, не production Stable feed. Изменение бинарника требует новых SHA-256 и подписи точных новых manifest-байтов.

UPDATER-01..25: обнаружение 5.0.0; получение signed manifest; Ed25519; SHA-256; схема; версия; anti-rollback; совместимость Relay; Tor-download; прерывание; возобновление; точный размер; hash; подтверждение; завершение; установка; перезапуск; данные; новые разделы; rollback; восстановление после restart failure; повторная проверка подписи; отказ неподписанному; отказ изменённому; отказ downgrade.

Проверьте соответствие `tag == "v" + version` и одинаковый tag в GitHub URL. Исторические parser sources в kit закреплены SHA-256, но их тестовые ключи не совпадают с release key и не доказывают весь E2E. Не отключайте verifier и не заменяйте pinned key ради получения PASS.

## Файлы доказательств

Kit создаётся `tools/package-native500.py` только после заморозки из точных 5.0 source/client ZIP. Все test/server/worker JAR остаются отдельно от app/. Серверные JUnit требуют JDK21 с jdk.httpserver; test-зависимости проверяются закреплёнными SHA-256. Упаковщик тесты не запускает и не выставляет PASS.

Каждая ручная строка: PASS, FAIL, BLOCKED или NOT_RUN. Для PASS укажите время, фактический стенд и доказательство с SHA-256. Не заменяйте подробное требование общим сообщением «всё работает». Не выдавайте предполагаемые или прежние результаты за испытание текущих артефактов.

Перед передачей отчётов уберите пароли, приватные ключи, TOTP seeds, bearer/lease tokens, реальные письма и содержимое личного архива. Имена аудиоустройств, пути и сетевые данные также могут быть личными. Полные crash dumps, аудиозаписи и расшифрованные файлы не включаются автоматически. Удаление личного содержимого в копии отчёта обозначайте явно; исходные результаты храните у владельца.
