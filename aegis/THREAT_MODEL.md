# Модель угроз

Защищаем содержимое сообщений и файлов от relay/VPS и кражи серверной БД при условии исправных клиентов, проверенных fingerprints и сохранности их приватных ключей. Защищаем локальный vault от чтения без пароля в пределах стойкости Argon2id/AES-GCM. Tor скрывает прямые IP собеседников друг от друга и от Java relay, но не устраняет анализ трафика.

| Угроза | Результат / ограничение |
|---|---|
| Утечка БД relay | Ciphertext, nicknames, public keys, хеши паролей и метаданные; ключей содержимого нет |
| Полный захват VPS | Возможны DoS, удаление/повтор, задержка, подмена directory при первом контакте; проверенный fingerprint предотвращает незаметную замену identity |
| Слабый пароль аккаунта | Offline brute force хеша; захват аккаунта не восстанавливает приватную идентичность, но может удалять очередь |
| Слабый пароль vault | Offline brute force может раскрыть identity и локальные сообщения |
| Кража долговременной identity | Нет forward secrecy: сохранившиеся прежние packets могут быть открыты |
| Кейлоггер/вредонос на клиенте | Может украсть пароль и plaintext; приложение это не исправляет |
| Root/Administrator на клиенте | Может читать RAM/диск, изменить приложение и перехватить ввод |
| Скриншот, камера, переписывание | TTL не уничтожает такую копию |
| Clipboard/cloud sync ОС | Явно скопированный пользователем текст может покинуть контроль приложения |
| Traffic correlation | Tor не гарантирует защиту от сильного наблюдателя обеих сторон |
| Повтор packet/ACK | Подпись, digest, messageId и tombstone предотвращают повторное письмо/reset TTL |
| Выключение устройства | Таймер не исполняется; expired ciphertext очищается при следующем открытии |
| Сбой питания / SSD snapshots | Atomic writes снижают риск; физическое удаление и полная crash consistency не обещаются |
| Блокировка Tor/Snowflake | Приложение остаётся offline; clearnet fallback отсутствует |

Граница доверия: relay — транспорт и реестр публичных ключей, не доверенная сторона для содержимого. Первичная проверка fingerprint обязательна для защиты от активной подмены relay. Сами binary format и схема управления ключами приложения требуют внешнего аудита; использование стандартных библиотек не отменяет возможные ошибки их соединения.

## Клиентское обновление1.0

Один пользовательский пароль используется для входа и локальных данных, с разными salts/KDF contexts для ключей. Работающий relay protocol1 получает исходный account password. Компрометация relay плюс кража encrypted vault даёт возможность открыть vault этим паролем. Отдельные letter password/FF1 code он не получает. ZIP exports имеют стандартный WinZip AES/PBKDF2-1000 KDF, filenames видимы и TTL их не удаляет. Обновления запускаются явно скачанным пакетом без HTTP updater. Backup/rollback хранят старый ciphertext и не обещают физическое стирание SSD.
