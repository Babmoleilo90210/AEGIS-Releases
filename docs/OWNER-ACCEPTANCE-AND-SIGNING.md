# Приёмка и offline-подпись АЕГИС 1.0.0

Сборки и контрольные суммы подготовлены. **Текущий статус — кандидат; `productionReady=false`.** GitHub содержит инструкции и changelog. Бинарные файлы Release, live `stable.json` и подпись пока не опубликованы.

Автоматически подтверждены 54 исходных теста, расширенный прогон 85 PASS / 1 Windows SKIP и 16 release/security tests. Проверки на настоящих Windows, CachyOS и действующем VPS ещё нужно выполнить. Ниже — порядок, после которого можно отдельно подтвердить публикацию.

## 1. Проверить полученный комплект

Распакуйте `AEGIS-1.0.0-release-signing-bundle.zip`. Внутри находится папка `AEGIS-1.0.0-release` с Windows ZIP, Setup, AppImage, исходниками, тестовым комплектом и unsigned manifest.

На CachyOS откройте терминал в этой папке:

```sh
sha256sum -c SHA256SUMS
sha256sum -c SIGNING-INPUT-SHA256
```

Все строки должны закончиться `OK`. При несовпадении остановитесь. Не редактируйте JSON в редакторе: подпись относится к точным байтам файла.

SHA-256 текущего `updates/stable.json`:

```text
2a613cce6d31b30f2cad70dd89f21e692d788c4148bc564d47b16f30730aed57
```

## 2. Проверить Windows и CachyOS

Распакуйте `AEGIS-1.0.0-native-acceptance.zip` рядом с распакованной Windows-папкой `AEGIS` или AppImage. Это отдельный тестовый комплект; обычному пользователю он не нужен.

**Windows:** откройте `Run-Windows.cmd`. Он использует Java из клиента; если папка другая, предложит выбрать её. Повторите при системном масштабе 100%, 125%, 150%, 175%, 200%. Программа создаст `AEGIS-native-Windows-*.json` рядом со скриптом.

**CachyOS:** дайте AppImage право запуска и запустите тест:

```sh
chmod +x AEGIS-1.0.0-CachyOS-x86_64.AppImage
bash AEGIS-1.0.0-native-acceptance/Run-CachyOS.sh
```

При другом расположении передайте путь к AppImage первым аргументом. Повторите на KDE Wayland и X11, если оба сеанса доступны. Результат — `AEGIS-native-Linux-*.json`. Если X11 недоступен, отметьте это отдельно, не пишите PASS.

`FAIL_OR_UNAVAILABLE` и SKIP не закрывают обязательную проверку. Если системное хранилище заблокировано, разблокируйте его штатным способом и повторите тест. Комплект использует случайный тестовый профиль, не требует паролей аккаунта и не меняет рабочий профиль АЕГИС. Отчёты не отправляются автоматически и не содержат пароли, ключи или адрес сервера.

## 3. Проверить реальное использование

Запустите обычные клиенты и используйте действующий Relay 0.2.0 / protocol 1. Сервер переустанавливать не нужно.

| Проверка | Что подтвердить |
| --- | --- |
| Чистый запуск | Windows Setup и portable, CachyOS AppImage работают под обычной учётной записью без отдельно установленной Java/Tor. |
| Tor | Встроенный Tor достигает 100%; соединение с выданным onion работает. При недоступном Tor клиент остаётся offline. |
| Вход | Регистрация тестового аккаунта при открытой регистрации; вход после закрытия и повторного запуска. |
| Обмен | Windows → CachyOS и ответ CachyOS → Windows через действующий relay, желательно из разных сетей. |
| Offline | Закрыть получателя, отправить сообщение, открыть получателя; доставка однократная, ACK удаляет очередь. |
| TTL | Выбрать 5 минут; после доставки сообщение удаляется по сроку, в том числе после перезапуска клиента. |
| Файлы | Отправить разрешённый архив; сверить SHA-256 исходного и полученного файла. |
| Данные | Контакты, идентичность и хранилище открываются после перезапуска обоих клиентов и ОС. |
| VPS | В плановое окно перезапустить VPS; relay и настоящий Tor unit возвращаются, БД и onion identity сохраняются. |
| Закрытие | АЕГИС завершает только свой Tor; повторный запуск не создаёт конфликт профиля. |
| Интерфейс | Иконка, popup, пароль, FF1, TTL, темы и масштаб работают без обрезания текста. |
| Обновление | На отдельной тестовой копии подтвердить запуск helper, startup ACK и rollback; production signature для этого пока не создана. |

Эти действия не выполняются тестовым скриптом. Отметьте фактический результат каждого пункта. Не публикуйте рабочую БД, приватные identity/onion keys или логи с пользовательскими данными. Перезагрузку VPS выполняйте только в выбранное вами окно обслуживания.

## 4. Подтвердить приёмку

Пришлите только `AEGIS-native-Windows-*.json`, `AEGIS-native-Linux-*.json` и заполненный список результатов. В итоговом комплекте есть `ACCEPTANCE-CONFIRMATION-TEMPLATE.json`: замените `PENDING` фактическими `PASS`, `FAIL` или `NOT_TESTED`. Непроверенные пункты остаются открытыми.

Отдельно нужно согласовать ограничения неизменённого сервера:

- Семь дней относятся к локальному разблокированию. Серверный bearer действует 12 часов и исчезает после перезапуска relay; затем снова нужен пароль аккаунта.
- Новый client AUTH KDF нельзя применить к уже существующим серверным password hashes без изменения relay и миграции аккаунтов. Текущая версия сохраняет прежний login protocol.

Если такой совместимый вариант вам подходит, напишите: **«Принимаю 12-часовую серверную сессию и 7-дневное локальное разблокирование; сохраняем auth Relay 0.2.0 / protocol 1».** Если нужны буквально семь дней сетевого входа и новый AUTH KDF, потребуется отдельная совместимая доработка сервера. Это согласование не заменяет native/E2E-тесты.

После проверки отчётов будет обновлён audit. **Не меняйте `productionReady` вручную.** Только когда все обязательные пункты действительно закрыты, подтверждайте: **«Подтверждаю приёмку указанных SHA-256 АЕГИС 1.0.0. Разрешаю публикацию после проверки моей offline-подписи».**

## 5. Подписать на offline CachyOS

Перенесите проверенный комплект на ваш компьютер для подписи и отключите его от сети. Используются локальные Python 3 и OpenSSL 3+. Private key остаётся на этом компьютере. Не отправляйте его, seed, passphrase или содержимое PEM.

Из папки `AEGIS-1.0.0-release` сначала:

```sh
sha256sum -c SHA256SUMS
sha256sum -c SIGNING-INPUT-SHA256
python3 -c 'import json; a=json.load(open("FINAL-RELEASE-AUDIT-1.0.0.json")); assert a["productionReady"], "STOP: приёмка ещё не завершена"'
```

**Сейчас последняя команда намеренно остановит процесс.** После завершения приёмки и получения обновлённого audit подпишите:

```sh
umask 077
python3 tools/sign-release-manifest updates/stable.json \
  "$HOME/.local/share/aegis-release-signing/release-private.pem" \
  --output updates/stable.json.sig
```

Если ваш существующий private key находится в другой папке, замените только путь к нему. Скрипт не обращается к сети; применяет стандартную Ed25519-подпись OpenSSL и проверяет соответствие встроенному public key. Если PEM защищён паролем, вводите его в запросе OpenSSL, не в аргументе команды.

Проверьте результат:

```sh
openssl pkeyutl -verify -pubin -rawin \
  -inkey updates/release-public.pem \
  -in updates/stable.json \
  -sigfile updates/stable.json.sig
python3 tools/verify-release-manifest updates/stable.json updates/stable.json.sig \
  --assets . --minimum-version 1.0.0
wc -c < updates/stable.json.sig
```

Ожидаются `Signature Verified Successfully`, успешная проверка manifest/assets и размер `64`. Подпись — raw bytes, не base64. Не редактируйте `stable.json` после подписи.

## 6. Что передать для публикации

Передайте **только `updates/stable.json.sig`** и подтверждение приёмки. Если manifest пришлось изменить, сначала нужен новый комплект с новым SHA-256 и повторная проверка; прежняя подпись к нему не подойдёт.

После проверки подписи и закрытия приёмки можно загрузить бинарные assets, повторно проверить их SHA-256, опубликовать Release v1.0.0 и согласованную пару `stable.json` / `stable.json.sig`. Подпись сама по себе не публикует Release и не запускает обновление клиентов.
